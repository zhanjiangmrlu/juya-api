# 场景缩略图与原图按需加载验收

## 实施

- 小程序与管理后台均通过 `sceneImageId` 选择素材，优先使用已有缩略图；缺失时按用户补充要求下载一次原图并在前端生成独立小图
- 小程序详情接口补充可空的 `thumbnail_id`，从当前授权发布版本对应的图片读取，不使用未发布候选图片；契约及小程序生成类型已同步，无数据库迁移
- 详情缩略图直接由图片组件加载，与原图下载、缓存、错误及重试分离；后台列表增加懒加载、失败占位和独立重试

## 故障证据与修复

微信开发者工具实测原生 `getImageInfo` 返回 `getImageInfo:fail invalid`，旧详情页把这一原图预处理失败直接当作小图不可用。现在小图不经过该预处理；用户查看原图时，若预处理失败，图片组件会直接读取同一个已授权原图地址，以实际图片加载事件判断成功或重试。诊断保留错误原因并遮蔽资源 URL

已在用户当前测试卡“商量活动计划”上观察到预处理失败后原图正常显示，加载提示消失，放大到 125% 正常。这是开发者工具验收，不是真机验收；未推断微信内部拒绝预处理的原因

## 用户补充：缺少缩略图时前端生成

- 两端封装 `clientThumbnail`，已有服务端小图继续优先使用；缺失时等比缩小到最大 360×540，不放大、不裁切，质量 80
- 小程序使用下载临时文件、原生压缩；实测本地原图的 `getImageInfo` 同样返回 `invalid` 时，采用 OffscreenCanvas 图片解码和导出。浏览器使用 Canvas 输出独立 JPEG data URL
- 缓存合并同一账号/发布版本的并发处理，最长 4 分钟、最多 32 项，账号清除时拒绝迟到结果；后台页面只持有当前页图像。不可用历史卡缺图时不请求其原图
- 正常生成后保留完整原图供查看；缩图失败时，用户仍可通过独立原图加载路径查看，不被压缩失败阻断
- 本地合成 API 响应主动移除缩略图字段，两端浏览器实际生成 360×540 图，点击仍为 2000×3000 原图。此场景必需先读取原图一次，不等同于服务端缩略图节省首次下载流量
- 微信开发者工具连接现有测试 API，商量活动计划与书评卡实际显示生成图；书评卡点击原图正常，原“暂无缩略图”消失。未扩大为手机真机验收
- 新增证据：私密目录内 `wechat-book-review-client-thumbnail.png`、`wechat-book-review-original.png`、`admin-client-thumbnails.png` 和 `mini-client-thumbnail-h5.png`

## 后台列表进一步缩小网络传输

用户要求将后台约100KB的现有缩略图再压小，并通过链接参数控制。现有私有图片接口未处理缩图参数，本轮增加管理端 `?thumbnail=list` 固定规格：最大144×216、WebP质量60、不放大、不裁切。只对已鉴权且ready的thumbnail素材生效；不带参数仍读取既有完整素材。列表统一通过 `sceneThumbnailURL` 封装参数与重试次数，原图查看保留原始地址；无服务端小图的浏览器生成路径同步使用144×216和质量60。

接口按不可变存储键和校验值缓存已编码的小图，每个管理API实例最多128项；每次命中前继续鉴权及读取素材状态，不改数据库或持久素材。HEAD与Range沿用生成结果的实际字节长度。新增回归先观察参数被忽略、尺寸仍为520×780而失败，实施后通过；覆盖字节量缩小、原图完整字节不变、HEAD/Range、退出后401、固定规格校验、缓存命中/容量与小图不放大。
