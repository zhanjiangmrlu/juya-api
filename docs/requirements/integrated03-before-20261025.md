## 0. 阅读方法与原型标记

- U代表用户端页面，A代表后台页面，P代表覆盖层或确认弹窗；同一页面的加载、失败、空数据是状态，不新增业务页面。
- “场景词汇卡”是包含中文标题、英文标题、场景图、完整音频、对话、词汇和可选语块的一整份内容。下文简称“卡片”。标题属于同一卡片同一发布版本，不以改名或补录英文另建卡。
- “词汇条目”是卡片内部的一个英文词汇、可选音标与可选本句释义，不能独立收藏；“语块”是可选的英文表达及中文释义。
- “收藏”仅指用户与整张卡片的关联；“复习”从收藏或学习记录再次进入同一场景详情，不另做翻卡页面；U01仅展示未完成卡。本次队列、历史完成和当天打卡分开处理，复习不重复增加累计已学数。
- 页面说明按“入口→布局→操作→结果→返回→异常”组织。原型需要同时绘制正常状态及指定关键状态，并按页面编号连线。
- 业务文案使用“中文标题、英文标题、场景图片、完整音频、场景对话、重点词汇、语块、保存草稿、预览并发布”；“卡片名称”是双标题的统称，不是要求拼在一个字段内。内部编号、版本、文件哈希和接口参数不作为管理员必填项。

## 1. 产品目标与本期范围

### 1.1 唯一学习主线

用户阅读说明、主动勾选同意并点击“同意并登录” → 服务端校验微信身份并识别／创建稳定账号 → 用户记录自动写入后台（联系方式可为空） → 进入学习列表查看本人学习数据 → 打开场景卡看图、听完整对话、阅读英文及按需展开译文 → 点击“已完成学习” → 自动更新累计已学、当天打卡和连续天数 → 收藏整卡并随时再次学习；来源队列可连续下一张，正文可查词，问题反馈和分享按第33—34章执行。

后台依次完成资料录入、核对、保存草稿、预览发布；用户列表和详情直接读取真实用户、完成与打卡数据。只有一种卡片模板，不恢复短文、语法等多模块。

### 1.2 本期保留与恢复

1. 明确的主动微信身份登录页，用户操作前不静默建立业务账号；不获取手机号、微信号或头像昵称。
2. 登录成功即进入后台用户列表，昵称、头像、手机号、微信号均不作为注册必填；联系方式在U09手动选填。
3. 学习／收藏两个底部入口；学习页显示已学多少张场景卡、连续天数及累计打卡天数。
4. 场景图上传、缩略图及大图预览；对话完整音频上传。
5. 词汇无音频文件上传，通过腾讯云接口生成并缓存发音；不做逐句播放、切片和跟读。
6. 完整英文对话及可展开／收起的全文中文译文；正文保留词汇高亮，任意正文英文词可点击中央查词弹窗。
7. 本句释义文字词汇列表、可选文字语块，空语块整区隐藏。
8. 整卡收藏指向最新发布版本，不提供独立单词／语块收藏。
9. 点击完成学习记录真实成绩，完成后支持来源队列下一张；U01只展示未开始／学习中，已完成在U06，独立学习记录入口。
10. 手工录入与单／多ZIP、DOCX配套资料导入，共用草稿、预览、发布；双标题贯通，完整音频支持MP3、M4A、WAV、AAC四类输入。
11. 后台单卡编辑、下线、删除、重新发布及排序；增加当前页明确选中集合的批量下线／删除，保留用户历史学习数据。
12. 后台用户列表和用户详情，查看可为空的联系方式、已学卡片、打卡与收藏数量。
13. U07只读资料、U08个人资料编辑、U09选填联系方式编辑；独立A07仍展示原三项统计。
14. U07与U03反馈双入口，U10—U12同条持续沟通，A08／A09管理处理及未读红点。
15. U01／U03好友、群、朋友圈分享，统一模板、主动登录后目标恢复，朋友圈单页安全承接。
16. 统一加载、空状态、隐私链接、图片占位与失败重试；A04按真实可恢复批次显示继续处理。

### 1.3 继续移出本期

| 功能 | 处理 |
|---|---|
| 权益中心、内容包、限时活动、三场景解锁 | 不恢复；本期明确发布的卡片向已完成登录的用户开放 |
| 联系状态核对、申请更正、多级审批 | 不恢复；联系方式通过用户主动填写／修改直接更新，后台只查看 |
| 消息中心、SLA倒计时、实时客服 | 不设置；第33章反馈时间线及入口未读是本轮确认的新能力 |
| 短文、长难句、语法及模块开关 | 不开发独立模板或占位入口 |
| 逐句精听、音频时间点／切片、跟读录音、评分 | 不提供，不申请麦克风权限 |
| 中央词库、OCR、AI释义、自动整篇翻译 | 不恢复；管理员提供本卡资料，正文通用词典查询按7.7单独定义 |
| 词汇／语块银行、单词收藏、翻卡 | 不恢复，收藏始终是整张场景卡 |
| 词汇图片、词汇音频上传、语块发音 | 不提供；只上传场景图与完整对话音频 |
| 排名、补签、强制听完、学习时长考核 | 不设置；主动完成学习即可记有效学习 |
| 用户批量操作、管理员改成绩／打卡、营销导出 | 不提供 |
| 独立工作台、复杂统计大屏、任务中心、复杂服务配置 | 不设置；保留轻量独立A07数据统计及学习页、用户列表／详情的学习统计 |

“移出本期”不授权删除真实历史数据。旧版迁移按第24章处理。

### 1.4 成功标准

- 新用户主动同意并登录成功，联系方式为空也能学习，后台立即出现同一稳定用户并计入用户统计。
- 用户能按需展开全文译文、听整篇音频、点击词汇发音，并收藏整卡。
- 完成按钮成功后，学习页与后台用户详情展示同一口径的已学卡片及打卡数据。
- 同卡重复完成不刷高累计卡数；跨天复习可形成新的有效学习日。
- 不需要的卡片可单独下线或删除；已有学习成绩不因此减少。
- 上传仍简单，管理员不填写内部ID、版本或接口参数。

## 2. 角色、导航与默认规则

### 2.1 角色与后台权限

| 角色 | 能力 |
|---|---|
| 已完成微信身份登录的用户 | 学习发布卡片、看译文／大图、播放、整卡收藏、标记完成、查看本人统计和学习记录、管理本人联系资料 |
| 单管理员 | 管理卡片和导入，查看用户与总体统计，处理A08／A09反馈及同条回复 |

身份使用稳定用户引用，微信号／手机号是联系资料，不作为合并账号或查找他人数据的凭证。管理员不从用户端获得编辑权限。

### 2.2 用户端导航与入口

- 未登录／会话失效进入U00微信登录；没有登录不返回正文、音频、收藏或个人统计。联系方式为空不是未登录或会话失效。
- 完成登录后默认进入U01。有效会话可复用，不要求每次打开重新填资料；会话失效需用户再次点击登录，不在后台悄悄重建身份。
- 底部仅“学习／收藏”；U01、U02显示底部导航。
- U01统计卡下显示独立整行“学习记录”入口；右上账号资料进入U07并聚合反馈未读，不增加“我的”底部导航。
- U03为二级详情，保留顶部返回，底部提供完成学习操作，避让安全区。
- U04为全屏覆盖层；U06、U07为二级页，返回来源，默认回U01。U08、U09由U07进入，完成或取消后回U07；U07再返回U01原位置。

### 2.3 后台导航

- A01成功后进入A02卡片管理。
- 业务导航为“卡片管理／批量导入／用户管理／数据统计／问题反馈”；问题反馈A08进入处理详情A09。A03从卡片管理进入；用户管理落地A05，点击用户行进入A06；数据统计落地A07。
- 用户详情仅查看，不提供手工改联系方式、已学数量或打卡成绩。
- 卡片管理可编辑、单独下线或删除；发布与导入仍分开。
- 腾讯云参数由服务端统一配置，不出现在资料上传流程。

### 2.4 统一默认

- U00只有“同意并登录”主入口。主动微信身份登录成功即建档；默认头像为句芽头像、昵称为“学习者”，联系方式允许为空，均可稍后在资料页补充。
- 详情首次进入仅显示英文对话，全文中文默认收起；点击“显示译文”在全部英文下方展开，再点“收起译文”隐藏。词汇／语块中文不受影响。
- 不自动播放。只有完整对话文件上传，词汇音频由服务端生成。
- 卡片首次完成按用户＋稳定卡片ID去重；当天学习及打卡按北京时间自然日去重。
- 跨天复习同一卡不增加累计已学卡数，但能形成当天打卡；同一天重复提交不重复计数。
- 卡片更新不重置完成，下线／删除不抹去已完成历史；U01未完成查询不得因新版或已取消收藏把已学卡重新显示。
- 收藏读最新发布版本，按有效收藏时间倒序；学习列表按后台排序。
- 不强制听完音频、看译文或收藏后才能完成，不做学习时长考核。

## 3. 页面、覆盖层与状态索引

### 3.1 用户端

| 编号 | 页面／状态 | 入口 | 下一步与返回 |
|---|---|---|---|
| U00 | 主动微信身份登录 | 未登录、主动退出、会话失效；不因联系资料缺失进入 | 勾选同意后点击“同意并登录”；成功回目标页，默认U01；失败留页 |
| U01 | 学习列表与统计 | 登录成功、底部学习 | 卡片U03、学习记录U06、账号资料U07、收藏U02 |
| U02 | 整卡收藏列表 | 底部收藏 | 有效卡U03，不可用卡U05；不检查联系方式是否填写 |
| U03 | 场景详情 | U01、U02、U06中的卡片 | 播放、译文、收藏、完成均原地；看图U04；返回原来源及位置 |
| U04 | 场景大图 | U03缩略图 | 关闭回U03原位置，译文与音频保持 |
| U05 | 卡片不可用状态 | 下线／删除卡的收藏或历史，或详情收到失效结果 | 显示安全摘要，可取消本人收藏；返回来源列表 |
| U06 | 学习记录与打卡记录 | U01统计或学习记录 | 查看已学／打卡，有效卡U03、不可用卡U05；返回U01原位置 |
| U07 | 只读账号资料 | U01右上角账号资料 | U08／U09、我的反馈U10及未读、隐私说明、退出；返回U01原位置 |
| U08 | 编辑个人资料 | U07编辑个人资料 | 头像、昵称；保存成功或取消回U07，有改动离开先确认 |
| U09 | 补充／修改联系方式 | U07对应入口 | 手动选填手机号、微信号；保存成功或取消回U07，有改动离开先确认 |
| U10 | 我的反馈列表 | U07我的反馈 | 提交U11、详情U12；返回U07原位置 |
| U11 | 提交问题反馈 | U10或U03反馈问题 | 分类说明及可选截图，成功U12，失败留输入，返回原来源 |
| U12 | 反馈详情与补充 | U10或提交成功 | 同条沟通及准确已读，返回U10／实际来源，失效卡仅摘要 |
| U03-P1 | 中央查词弹窗 | U03任意正文英文词 | 查询及手动发音，关闭恢复阅读状态 |
| U03-P2 | 当前队列完成弹窗 | 学习／复习／收藏队列结束 | 返回学习页或留在当前详情 |
| U00-P1 | 隐私及用途说明 | U00、U07的说明入口 | 关闭回实际来源页，保留勾选／输入／滚动；不代替用户勾选 |
| U07-P2 | 退出登录确认 | U07退出登录 | 确认后停播清会话回U00，取消留U07；服务器成绩与收藏保留 |

### 7.3 译文状态

### 7.5 排版、版本与失败

长词、音标、释义及来源句自然换行；英文和音标优先相邻，超宽时音标换行。缺释义或音标只隐藏对应部分。词汇列表同词不同本句意思各自绑定来源，通用词典查询不改写管理员资料。图片、查词或发音失败均不阻断译文、整卡收藏或合法完成。

刷新只读取同一最新发布版本，不混用新旧对话／词汇。无唯一来源锚点时明确从顶部重载，不猜配旧位置。收到下线／删除时关弹窗并停播，转U05；学习与打卡历史不回退。

### 7.6 中英文标题统一展示

学习、详情、收藏、记录及分享复用titleZh／titleEn同一发布版本，中文在上、英文在下，自然换行；完整译文开关不影响标题。历史已发布缺英文只用已有中文，不渲染空行或假值。草稿补录未发布不能提前进入用户端、分享或反馈来源展示；更新不创建另一张卡。

### 7.7 U03-P1中央查词弹窗

- 对当前发布英文对话中的任意英文单词开放点击查询，不以是否高亮限制；标点不作为词汇，常见英文缩写、连字符和撇号按完整词边界处理，不将纯标点提交。
- 中央弹窗展示点击原词、适用原形、可用音标、中文释义、发音按钮和关闭按钮；内容过长在弹窗内部滚动，点击遮罩或关闭按钮关闭，不新建独立查词页。
- 仅当点击位置对应非空且已确认的本句释义时优先显示“本篇释义”；本篇条目没有释义或非本篇词时，查询并标注“词典释义”，不显示空的本篇解释。同一拼写在不同句子有不同本句释义时按点击位置匹配；位置不唯一时不猜配，改用明确标注的词典释义，不改后台资料。
- 常见复数、时态等自动识别原形，例如went显示点击词went及原形go。原形识别失败时不猜原形，但仍展示已取得的本篇或点击原词词典释义；仅释义查询确实无结果才显示“暂未找到这个单词的释义”。网络失败显示“查询失败，请重试”，无假解释，无AI补写。
- 点词只打开释义，原整篇播放状态保持；点喇叭才暂停整篇并播放当前明确标注的读音目标。词形与原形不同，主发音按点击原词，不能用原形音频冒充原词；原词发音不可用则明确提示。
- 点击另一个单词切换到最新目标，旧查询迟到结果不得覆盖；切换目标或关闭弹窗停止弹窗发音。关闭后保持当前卡原阅读位置及译文状态，整篇不自动续播。
- 任意查询和发音均经本人有效会话与当前可学卡片校验；客户端提交卡片／版本及正文位置，服务端验证该原词来自正文后返回受控目标，不能变成任意文本TTS或自由输入翻译。
- 复用已有腾讯云受控发音与缓存规则；不向词典或TTS发送微信号、手机号、反馈截图、用户身份明文，不在小程序放供应商密钥。
- 本轮定义词典查询、词形识别、结果来源及失败能力，不采购或绑定词典供应商；技术接入前另核实数据来源、授权、覆盖率与用量。无释义仍可继续场景学习。
- 保留下方重点词汇／语块；弹窗和词汇行均不新增单独收藏，只保留整卡收藏。

## 8. U04 大图预览与U05不可用状态

### 8.1 U04 大图预览

- 使用场景原图，不把列表缩略图放大冒充清晰原图。
- 全屏等比显示，不裁去学习文字；支持双指缩放及放大后的平移。
- 关闭按钮／系统返回关闭覆盖层，不退出整个场景。
- 打开、关闭、缩放不改变详情滚动位置、译文展开、收藏、完成和音频播放状态。
- 大图加载失败在覆盖层内重试或关闭；不阻断详情文字学习。
- 覆盖层期间收到卡片下线、删除或账号不可用结果时，关闭大图并进入相应不可用状态，不继续展示失效资源。

### 8.2 U05 收藏内容不可用

- 这是U03的状态，保留可识别名称和不可用说明，不显示完整对话、词汇、音频或可提交的完成按钮；历史完成与打卡保留。

- 本人仍有有效收藏时显示“取消收藏”；请求失败保留记录并原地重试。
- 取消后显示“已取消收藏”，允许返回；不出现可再次收藏或完成已下线／删除内容的按钮。
- 从U02进入回U02，从U06已学／打卡记录进入回U06原标签及位置；U01遇到并发停用返回U01，无来源回U01。
- 下线卡重新发布后可读取最新内容，未取消收藏恢复正常；已删除卡不能通过旧页面重新发布，只保留历史摘要。

## 9. 音频统一规则

### 9.1 完整音频状态

| 当前状态 | 用户操作／事件 | 下一状态 | 页面反馈 |
|---|---|---|---|
| 未播放 | 点击播放 | 加载中→播放中 | 同位加载，成功后显示暂停图标 |
| 加载中 | 再次点击 | 保持当前请求 | 不重复取址或创建播放器 |
| 播放中 | 点击暂停 | 已暂停 | 位置保留，图标变为播放 |
| 已暂停 | 点击播放 | 从当前点继续 | 不从头重播 |
| 播放中／已暂停 | 拖动进度 | 使用新位置播放／保持暂停 | 不触发逐句模式 |
| 播放结束 | 点击播放 | 从头播放 | 进度归零 |
| 加载或播放失败 | 点击重试 | 重新取有效资源并播放 | 尽量从有效的已知位置继续，文件变化则整体刷新 |
| 任意播放状态 | 离开详情 | 停止 | 清理监听与临时播放状态，再进入不自动恢复 |

“完整音频”表示只使用一份整篇文件，暂停、继续和拖动进度不等于逐句精听。没有单句按钮、句子起止时间或切片播放接口。

### 9.1.1 完整音频倍速

- 默认1倍，用户点播放器内“1× 倍速”展开五档：1、1.25、1.5、1.75、2倍。当前项标记选中；点选后立即生效、收起选择区，显示所选倍速。再次点倍速按钮可收起选择区。
- 倍速只影响完整对话音频；不影响词汇发音、资料、收藏、完成或打卡。使用同卡同版本的一份完整播放资源；必要格式转换允许按第15.9节生成整篇播放副本，但不按倍速生成多份音频、不做逐句切片。
- 播放中切换保持播放位置与播放状态；暂停中切换保持暂停。尽量保持原音高。进度与时长仍显示原始音频时间。
- 词汇发音暂停整篇，保留位置和倍速；用户手动继续时沿用倍速。同一学习会话中，看大图、译文切换、暂停／继续、切换场景均保留倍速；重启学习会话恢复1倍。
- 加载或播放失败后重试保留倍速；客户端不因倍速切换重复提交学习行为。

### 9.2 词汇发音

1. 管理员提供词汇英文、有效来源及选填的本句释义、音标，不上传单词音频。
2. 下方词汇列表点击英文或喇叭仍提交受控词汇引用。正文点词仅打开7.7弹窗，点弹窗喇叭才发音；未配置词须由服务端校验当前卡片／版本／正文位置并签发受控目标，不能直接提交任意文本。
3. 有匹配缓存则播放；未命中时由服务端调用腾讯云生成、校验并缓存，再返回受控音频。
4. 不向腾讯云发送用户身份、收藏清单、微信号、手机号或本句中文释义；客户端不持有密钥。
5. 英文拼写、实际读音和音色等合成配置共同决定缓存；已确认不同读音不能因拼写相同错误复用。具体读音能力按接入的官方接口核对，不将音标文本直接视为受支持的语音指令。
6. 同一目标并发合并为一次任务。临时错误最多自动重试2次，永久错误不自动循环；手动重试受服务端预算与冷却控制。
7. 未准备好时在词汇行或中央弹窗相应位置轻量加载，不跳转“生成中”页面；已有缓存及单词读音不受完整音频倍速影响。
8. 点击另一个词汇立即停止旧发音；重复点击正在播放的同一词汇，从头重播。
9. 发音失败显示“发音暂不可用，点击重试”；本句释义、图片、译文、完成学习与整卡收藏仍可用。
10. 后台预览使用同一词汇发音服务，可以试听。已发现读音错误的条目先留草稿核对，不以错误读音作为合格结果发布。

### 9.3 防叠播优先级

| 新动作 | 已有完整音频 | 已有词汇发音 |
|---|---|---|
| 播放一个词汇 | 暂停并保留位置 | 停止旧词汇，再播放新目标 |
| 手动播放完整音频 | 从所选位置播放 | 停止词汇 |
| 打开大图 | 保持 | 保持 |
| 仅打开查词弹窗 | 保持 | 停止上一弹窗目标，不自动播放 |
| 关闭查词弹窗 | 保持已有状态，暂停的不自动续播 | 停止弹窗内发音 |
| 收藏／取消、译文展开／收起、完成提交 | 保持 | 保持 |
| 词汇播放结束 | 保持暂停，等待用户继续 | 结束 |
| 离开详情／预览 | 停止并清理 | 停止并清理 |

后台预览关闭后停止预览音频，不影响原编辑资料。

## 10. 整卡收藏状态与数据关联

### 10.1 操作规则

| 状态 | 文案／操作 | 处理结果 |
|---|---|---|
| 未收藏 | 收藏 | 提交当前已发布卡片引用 |

- 收藏列表的当前名称和图片取最新发布内容；不可用时仅用最后发布的摘要识别来源，不开放历史正文。
- 草稿、导入候选和未发布修改不会改变前端收藏显示。
- 收藏／取消不触发学习完成或打卡，不改变已学总数、连续天数及后台展示顺序；只有主动完成操作按第11章计数。

## 11. U06 学习记录、完成与打卡统计

### 11.1 页面布局与入口

U01已学数字进入U06已学标签，连续／累计数字进入打卡标签；统计卡下独立整行“学习记录”恢复上次标签，首次默认已学，顶部回U01。上方展示“累计已学N张场景卡、连续打卡N天、累计打卡N天”，同时显示今日打卡状态。三组统计中，数字与对应说明使用同一水平中线居中；多位数及零值不偏移，点击目标不变。

下方两个同页标签：

| 标签 | 列表内容 | 点击行为 |
|---|---|---|
| 已学卡片 | 每张已完成卡片一行，左缩略图、右中英文标题、首次完成／最近学习时间及可用状态，按最近学习倒序 | 有效卡进入U03，返回恢复本标签与位置；下线／删除卡进入U05 |
| 打卡记录 | 有效学习日期倒序，每日显示日期与当天完成的不同卡片数 | 点击日期原地展开当日卡片，点击可用卡进U03；无补签操作 |

新用户显示0及“完成一张场景卡，开始记录学习”，按钮“去学习”回U01。历史卡片不可用仍保留最后安全中英文标题（英文原缺失则不占位）、学习时间与成绩，不提供旧全文。有效卡名称按第7.6节读取最新发布双标题。

### 11.2 统计口径

| 指标 | 唯一口径 |
|---|---|
| 累计已学场景卡数 | 本人首次完成过的不同稳定卡片ID数量，同卡只计1张 |
| 卡片已完成标记 | 该用户该卡至少一次成功完成；与是否收藏、是否新版无关 |
| 当天完成卡片数 | 同一北京时间自然日完成的不同卡片数，复习旧卡可计入当日 |
| 当天打卡 | 当天至少一次合法卡片完成成功即自动打卡，每天最多一次 |
| 累计打卡天数 | 本人有有效学习的不同日期数，不因中断、下线或删卡清零 |
| 连续打卡天数 | 按本章北京时间连续有效日期计算，漏过整天才中断 |
| 最长连续天数 | 历史最长连续有效日期长度，U06与后台详情可显示 |
| 最近学习时间 | 最近一次成功完成新卡或复习的服务器时间，不以打开详情代替 |

不统计单词已学数量、浏览次数、音频时长和单词发音次数。收藏操作和单纯进入／播放不形成完成或打卡。

### 11.3 完成事务与同步

1. 用户主动点击U03完成操作，服务端校验用户已登录、卡片当前可学、来源版本有效。
2. 首次完成时创建用户＋卡片的唯一完成记录；保存首次完成时间、最近完成时间及可追溯发布版本。
3. 同日为用户＋卡片＋日期创建或复用一次每日学习记录，不因同日多次提交重复计数。
4. 为用户＋日期创建或复用打卡日，计算累计与连续指标。
5. 完成记录、每日记录与打卡在同一事务或等效一致操作中提交；失败不能只显示完成而无打卡，或只打卡无完成来源。
6. 响应返回本卡最终状态、有效日期、累计已学、连续与累计打卡及“本日是否首次打卡”。
7. U03原位显示真实结果，U01/U06回到前台或返回时同步；A05/A06下次查询读取同一数据源，不另算一套口径。
8. 重复请求、并发设备、超时重试均使用服务端幂等，不靠前端禁按钮保证唯一。

第一次完成新卡使累计已学＋1；同卡隔日复习仅更新最近学习与当天学习／打卡，不增加已学总数。发布新版、取消收藏、卡片下线或删除都不减少已有合法成绩。

### 11.4 连续天数与跨日

- 日期使用服务端Asia/Shanghai自然日，00:00至次日00:00；客户端改时间不能补签或提前计天。
- 今天已打卡：连续天数截至今天。
- 今天尚未打卡但昨天已打卡：仍展示截至昨天的连续天数，并明确“今日待打卡”；今天完成后续上，不在当天凌晨立即把昨天成绩清零。
- 今天、昨天都无打卡：当前连续为0；下一次有效学习从1开始。
- 同日完成多张卡，累计已学按各卡首次情况增加，但打卡天数只增加一次。
- 完成按钮跨午夜时，以服务端首次成功接受该次操作的日期归属，不允许用户指定历史日期。
- 若午夜前操作已成功、午夜后重试同一幂等请求，返回原日期结果，不额外创建新一天；要完成新一天学习须重新读取状态并主动发起新的操作。
- 离线／失败不先计打卡，不补写客户端声称的过去日期。恢复网络后成功提交按服务端接受日期算。
- 页面跨日回到前台或重新操作时刷新“今日已完成”状态；旧卡可变为“完成本次复习”。
- 不提供补签、排名或管理员手工改连续天数。

### 11.5 记录状态与原型

需绘制：首次0记录、今日待打卡、今日已打卡、昨天连续仍待今日续上、已学卡片列表、打卡日期展开、同卡隔日复习、完成处理中、失败／未知结果、历史卡片已下线／删除、跨日状态刷新。

完成成功仍留U03并按7.4／7.8显示下一张或结束弹窗，不新增成果页；学习记录与用户后台均只读展示真实记录。本次复习队列推进与当日幂等计数分开，今天已完成仍可继续下一张。

## 12. U07账号资料、U08个人资料与U09联系方式

### 12.1 U07 入口、只读布局及返回

入口为U01右上角“账号资料”。进入时读取当前账号资料，保留U01原位置；顶部或系统返回回U01该位置。资料加载失败原位重试，不把失败误显示为“未填写”。

从上到下：

1. 当前头像、昵称及“编辑个人资料”入口，点击进入U08。未设置时展示句芽默认头像和“学习者”。
2. 已提供的联系方式，只读展示。手机号默认脱敏，微信号按已保存值展示；未提供的单个字段不预留空行。两项均无值时显示“未填写联系方式”及“补充联系方式”，否则显示“修改联系方式”；均进入U09。
3. “我的反馈”进入U10，存在未读回复时显示红点；入口本身不清除各记录未读。
4. 隐私说明入口采用明确链接色及点击反馈，打开U00-P1，关闭回U07原位置。
5. 底部次要操作“退出登录”，打开U07-P2。

头像与资料入口、联系方式、隐私说明按紧凑分组排列；分组间距18px左右、列表行至少48px高，退出登录与上一组间距约28px。

首屏不放输入框、“保存资料”“重新授权”或“移除手机号”。不向用户展示“手填未验证”等技术来源状态；后台保留真实来源。联系方式为空不显示“账号未完成”等拦截文案。

### 12.2 U08 编辑个人资料

| 项目 | 规则 |
|---|---|
| 入口与布局 | U07编辑个人资料→顶部返回／取消→头像选择→昵称输入→保存；说明头像昵称仅用于展示 |
| 头像 | 用户主动选择图片，选择后显示待保存预览；取消选择不改当前已保存头像，不自动读取微信头像 |
| 昵称 | 用户主动填写；未设置时使用“学习者”，不自动读取微信昵称；空白输入按未设置处理 |
| 保存条件 | 有资料变化且头像已准备好；上传中／保存中禁止重复提交；无变化时可直接取消／返回 |
| 成功 | 更新同一稳定账号资料，返回U07显示新头像昵称，U01问候与A05/A06下次查询同步；学习、收藏、打卡与注册时间不变 |
| 取消／无修改返回 | 回U07原位置，不提交未保存预览或输入 |
| 保存／上传失败 | 就近说明并保留当前可恢复的选择与输入，旧有效资料不变；上传失败先重试或重新选择，不能保存悬空头像引用 |
| 有修改时离开 | U08-P1：继续编辑留页；保存后离开成功回U07，失败仍留U08；放弃修改回U07并保留旧有效资料 |

正常保存成功也回U07；外层U07返回U01原学习位置。个人资料修改不是注册或切换账号，不新增用户，不改变任何学习数据。

### 12.3 U09 联系方式编辑

从U07“补充联系方式／修改联系方式”进入同一二级页。布局为顶部返回／取消 → 选填用途说明 → 手机号输入（选填）→ 微信号输入（选填）→ 保存。字段带入本人已保存值；手机号在本人编辑页可查看和修改原值，U07默认脱敏。

- 两个字段均由用户手动填写；没有授权按钮、短信验证码、重新授权或删除／移除入口。明确“联系方式选填，不影响学习；手动填写暂不验证归属”。
- 原来两项均未填写时，保持为空即可取消／返回U07并继续学习；没有变化不产生空提交，不要求至少填一项。
- 用户可只填手机号、只填微信号或两者都填。填写内容去除首尾空白；对非空新值作基础格式校验，错误紧邻对应字段说明，不把格式正确等同真实归属或实名。
- 沿用已确认的无移除规则：已有手机号或微信号被清空时，提示“已有联系方式不能通过清空删除，请保留或修改”；不提交该次保存，原值仍生效。原本未设置的字段保持为空不报错。
- 两个字段通过同一“保存”操作提交本次变更；不自动提交输入、不因返回U07保存草稿。服务端仅更新明确变更且通过校验的字段，未修改字段及其历史来源保持原样；保存不能出现一项成功另一项却显示整体成功的分裂结果。
- 新增／修改值来源记“用户填写／未验证”，按字段记录修改与用途同意；界面不显示技术标签。历史有可靠来源的未改字段保留来源；任一字段被手动修改后该字段更新为用户填写来源。
- 保存中防重复点击；成功回U07显示确认结果，A05/A06下次刷新同步，U01账号身份及学习数据不变。
- 校验失败保留输入并定位；服务端失败保留旧有效资料与当前输入；超时未知先查询本人最终资料，核对本次操作结果后重试，不伪造成功。
- 其他设备已改同一资料时，提示重新获取并核对，不能用旧页面未修改字段覆盖较新资料。

### 12.4 未保存、会话失效与退出

- U09有未保存修改离开时打开U09-P1：继续编辑留页；保存后离开仅在校验和保存成功后回U07；放弃修改丢弃本次输入、回U07保留服务器旧资料。U08按U08-P1同样处理。
- 联系方式输入或头像昵称修改不触发任何微信手机号授权，不存在先保存再自动拉起授权的流程。
- U08/U09会话失效时停止提交并回U00，敏感资料不写URL或公开缓存；再次同一身份登录后回U07获取真实资料。未提交编辑可在安全的短期内存中恢复并提示重新核对；无法安全保留时说明本次未保存，不能自动提交。
- U07-P2取消留U07；确认退出停播、清客户端会话和个人资料缓存回U00。服务端学习与收藏保留，退出不等于注销或删除个人数据。
- U00-P1说明账号身份、选填联系方式及学习记录各自用途；从U07打开关闭回U07，不跳登录页，不覆盖输入或勾选状态。

### 12.5 必画状态

U07无联系方式、仅手机号、仅微信号、两者都有、默认头像昵称、资料读取失败、隐私说明和退出确认；U08头像选择／取消、昵称编辑、保存中／失败／成功、未保存离开；U09空资料可返回、单字段／双字段编辑、格式错误、已有字段清空拦截、保存中／失败／未知结果、未保存离开和会话失效。状态不是额外业务模块。

排序模式只针对全部已发布卡；不改收藏顺序、已学／打卡数据或正文版本。未保存离页A02-P3提供继续调整／保存后离开／放弃；保存失败保留临时顺序。

### 13.5 下线与删除的区分

| 动作 | 后台效果 | 用户端效果 | 历史成绩 |
|---|---|---|---|
| 下线 | 保留管理列表和编辑能力，之后可重新发布 | 从学习列表移除，收藏／已学记录显示暂不可用 | 全部保留 |
| 删除 | 业务删除，移出主列表并停用编辑／发布，不提供回收站业务页 | 不再可学，已有收藏／历史仅显示已删除摘要 | 已学总数、学习日期和打卡继续保留 |

“删除”本期采用业务软删除：保留稳定卡片ID、删除标记及必要历史引用，不把删除卡片等同于删除用户成绩。素材是否可清理由服务器按引用另行处理；本次文档不执行真实文件或数据库删除。

### 13.6 确认、并发和失败

- A02-P1：“下线这张卡片？”显示名称；说明停止前端学习、可重新发布、历史学习记录保留。按钮取消／确认下线。
- A02-P4：“删除这张卡片？”显示名称；说明移出后台主列表、用户不能继续学习，已有完成及打卡保留。按钮取消／确认删除。
- 已发布整卡也可直接删除，服务端在同一操作中停止发布并标删除，不要求管理员先下线再点第二遍。
- 点击处理期间禁重复；重复删除返回最终状态，失败保留原行并提示重试。
- 删除时存在新版本或其他窗口更改须重新获取当前影响并确认；旧页面保存／发布已删除卡片被拒绝，不复活整卡。
- 收藏取消、完成保存与删除并发按服务端事务顺序：先成功的合法完成保留；删除已生效后不能新增学习完成或收藏。

### 13.7 当前页批量下线与批量删除

#### 13.7.1 入口与列表选择

入口为后台“卡片管理”。每行提供勾选框，表头支持当前页全选、半选和取消选择。

- 选中后显示“已选择N张”“批量下线”“批量删除”“取消选择”。未选中时不提供可提交的批量操作。
- 全选仅作用于当前页，不隐含选中其他页或全部搜索结果。
- 点击“取消选择”清空当前勾选，留在列表原位置。
- 翻页、搜索或切换筛选时清空勾选；有原选择时提示“选择已清空”。

#### 13.7.2 批量下线

点击“批量下线”后打开确认框，读取选中卡片的当前状态。

| 项目 | 规则 |
|---|---|
| 适用范围 | 已发布卡片；草稿和已下线卡片不重复执行下线 |
| 确认内容 | 选中数量、可下线数量、名称，以及不适用项和原因 |
| 影响说明 | 下线后用户不能继续学习该卡，后台保留卡片，可重新发布；已有学习记录及打卡保留 |
| 按钮 | “取消”“确认下线N张”；可下线数量为0时禁用确认 |
| 取消 | 不提交，关闭确认框，保留原勾选、页码及位置 |
| 确认 | 仅处理确认框明确列出的适用集合，处理中禁止重复提交 |

#### 13.7.3 批量删除

点击“批量删除”后打开确认框，展示选中卡片的名称、状态、数量及删除影响。

- 可删除草稿、已发布、已下线卡片。已发布卡片可直接删除，不要求管理员先下线。
- 删除采用业务软删除：移出卡片管理主列表并停止用户访问，保留历史学习引用，不提供恢复入口。
- 用户已有已学数量、完成记录和打卡数据不因删除而减少。
- 按钮为“取消”“确认删除N张”；没有可删除项时禁用确认。
- 取消不提交并保留原选择；确认后锁定本次集合，防止重复点击。

#### 13.7.4 结果、返回与异常

- 结果显示“成功N张、失败M张、跳过K张”，逐项说明失败和跳过原因。
- 成功项更新列表，失败项保留真实状态；成功不随其他项失败而回滚。
- 结果区提供“重试失败项”，只处理原失败集合，不重新选择当前页全部卡片，也不重复执行成功项。
- 操作超时或结果未知时先查询最终结果，不直接视为失败重新提交。
- 若确认后卡片状态或版本已变化，提示重新核对，不覆盖最新状态。
- 完成后清空原勾选，保留搜索／筛选，刷新当前列表、总数及相关已发布数量；分页回退规则见第13.9节。
- “全部”筛选下的卡片下线后仍作为已下线卡显示；“已发布”筛选下，下线成功项才移出当前结果。

### 13.8 列表场景原图预览

#### 13.8.1 入口与操作

入口为卡片管理列表中的场景缩略图。点击后在当前列表上打开原图预览覆盖层。

- 点击缩略图只打开大图，不进入卡片编辑，不改变该行勾选。
- 展示与该行卡片版本一致的原图，不把低清缩略图拉伸当成原图。
- 已发布卡展示当前发布图，草稿展示草稿图，已下线卡展示最后发布图；未发布修改不替代当前发布图。
- 图片保持原始比例；支持缩放、放大后拖动，长图可以完整查看。
- 提供清晰的“关闭”入口，不增加编辑、保存或发布操作。

#### 13.8.2 返回与异常

- 关闭后回到卡片列表原条件、页码及滚动位置，保留原勾选状态。
- 加载期间显示“图片加载中”；失败显示“图片加载失败”及“重试”，不让整个列表失效。
- 没有图片时显示“暂无场景图”，不提供空图片的放大入口。

### 13.9 固定每页10条及返回恢复

#### 13.9.1 页面与接口规则

- 卡片管理固定每页10条，剩余数据翻页显示，末页允许不足10条。
- 分页区显示总条数、当前页、总页数、“上一页”“下一页”；首末页禁用对应越界按钮。
- 没有匹配数据时显示“共0条”和空状态，翻页按钮禁用，不显示无效或负页码。
- 服务端按搜索／筛选条件执行分页，每页最多返回10条，不能只在前端隐藏超出的全量数据。
- 同一查询使用稳定顺序，避免同值数据在相邻页重复或遗漏；本次不新增或修改排序功能，也不扩展跨页拖拽排序或跨页批量选择。

#### 13.9.2 跳转与返回

| 动作 | 分页及状态 |
|---|---|
| 搜索或修改筛选 | 回第1页并重新查询，清空原勾选 |
| 上一页／下一页 | 保留搜索／筛选，查询目标页并清空原勾选 |
| 编辑后返回 | 恢复原查询条件、页码和位置，刷新对应真实状态 |
| 预览关闭或返回 | 恢复原查询条件、页码和位置；大图另保留勾选 |
| 删除或下线后当前页不存在 | 保留条件，回退最近有效页；例如第2页最后一条移除后回第1页 |
| 仍有有效当前页 | 留在当前页刷新，不无故跳回第1页 |

#### 13.9.3 异常

列表读取失败时显示“列表加载失败，请重试”，保留查询条件和页码；不能用空状态或总数0替代请求失败。只有确认查询结果确实为空时才显示空状态。

2. 学习概况：累计已学卡片、当前连续、累计打卡、最长连续、今日状态及当前整卡收藏数。

### 14.4 用户页面异常与画板

用户不存在／不可用时说明并返回A05，不展示他人资料；联系为空是正常状态。资料与统计可独立失败、独立重试，失败显示“暂未获取”，不能替换为假0。卡片下线／删除不减少合法历史成绩。必画新注册0学习且无联系、正常列表、搜索空、今日注册、今日打卡、组合筛选、详情标签、历史不可用卡、资料失败与返回恢复。不增加用户删除、禁用、成绩修改、补签、联系核对或营销操作。

### 14.5 A07 数据统计布局与口径

入口为独立“数据统计”菜单。页面顺序：标题“数据统计”→ 统计日期（北京时间）与更新时间 → 刷新按钮 → 三项数字。日期和更新时间由服务端返回，三个指标使用一致统计时点。

| 指标 | 唯一口径 | 点击关联 |
|---|---|---|
| 用户总数 | 成功注册的稳定用户账号去重，不包含管理员；无联系方式、0学习用户均计入 | A05全部注册、全部打卡，清旧搜索和筛选 |
| 今日新增用户 | 北京时间今日首次成功注册的稳定账号；不以登录、补资料、收藏或完成代替注册 | A05今日注册、全部打卡，清旧搜索 |
| 已发布场景卡片数 | 当前已发布且未删除的不同稳定卡片数，同卡多次发布只计1张 | A02已发布筛选，清旧搜索及其他会缩小集合的条件 |

- 首次建档成功只增加一次用户总数和当日新增；并发登录、响应丢失后恢复、重新登录、换设备、补填联系方式或修改头像昵称不增加数量，不改变首次注册日期。
- 草稿、导入暂存、仅保存已发布卡候选均不增加已发布数量；发布后增加，下线／删除后减少；下线卡重新发布后恢复，发布新版本不重复加数。已删除卡不能通过旧窗口复活。
- 三项数字只读，不提供手填。注册与打卡筛选独立；管理员账号不计学习用户，内容操作不会创建用户。

### 14.6 A07 加载、点击、返回与跨日

|---|---|
| 首次进入／点击刷新 | 请求最新一致统计，加载中显示占位，不能先显示0；刷新中防重复请求 |
| 成功且真实为0 | 明确显示0；点击仍进入对应列表空态 |

## 15. A03 卡片编辑

### 15.1 页面公共规则

顶部：返回、卡片名称或“新建卡片”、当前草稿／发布状态。正文分四组，底部固定“保存草稿”“预览并发布”，避让最后一组内容。

- 所有资料按从上到下的自然顺序填写，不使用多个平行设置页。
- 未填完整仍能保存草稿；发布问题在本页定位，不要求跳校对中心。
- 保存中禁重复提交；成功显示“草稿已保存”，停留当前页。
- 草稿保存不改前端；发布成功回A02并定位该卡片。
- 不自动保存未确认变更；有未保存修改离开时打开A03-P2。
- 同一会话切换预览、展开词汇或暂时查看其他区域不丢输入与文件引用。
- 新建空白页直接离开无需提示；有输入／上传但未保存时才提示。

### 15.2 第一组：基本资料

| 字段／控件 | 规则 | 帮助与反馈 |
|---|---|---|
| 中文标题 | 草稿可缺，新卡发布及已有卡新版本发布必填 | 独立输入框，如“在咖啡店点单” |
| 英文标题 | 管理员提供，草稿可缺，新发布必填 | 独立输入框，如“Ordering at a Coffee Shop”；不自动翻译／OCR生成 |
| 场景图片 | 发布必需一张；PNG／JPEG／WebP可解码静态图 | 上传即显示预览；按钮“更换图片”“查看大图” |
| 完整音频 | 发布必需一份完整文件 | 上传后显示文件名、实际时长、播放／暂停及“更换音频” |

图片自动生成缩略图，不要求管理员再上传封面。完整音频输入范围为MP3、M4A、WAV、AAC四类，真实解码校验及播放副本规则见第15.9节；其他格式明确提示不支持。

本组只上传词卡完整对话音频；词汇与语块区不提供音频文件上传或替换控件。

上传按第15.7节显示真实进度、失败原因和同位重试。换图片须新文件成功；换音频须上传、校验及必要转换完成，才切换编辑稿引用。失败不丢旧文件；已发布版本继续使用原素材直到重新发布。资源大小和传输上限由部署配置统一给出，并在选择文件前明确提示，不逐卡填写。

### 15.2.1 双标题录入、保存与版本

不能只给页面补一个英文文本位置。需同时检查标题是否被录入、DOCX是否提供、解析是否读取、接口是否保存并返回，以及页面是否绑定。

卡片基本资料将名称区明确为两个独立字段：

| 字段 | 规则 |
|---|---|
| 中文标题 | 卡片中文名称，示例“为戏剧社挑一个剧本” |
| 英文标题 | 卡片原英文名称，示例“Choosing a Play for Drama Club” |

- 编辑页名称区从上到下展示“中文标题”“英文标题”，不要求把两种语言拼在同一个输入框。
- 草稿允许任一标题暂缺，缺少项就近标记；新卡发布或发布已有卡片的新修改时，两项均须填写完整。
- 保存失败保留输入及原有效资料；返回列表后保留原查询条件、页码与位置。
- 英文标题由管理员提供，保留正确的拼写、大小写和标点。不根据中文自动翻译，不从图片自动OCR生成，不用文件夹名猜测缺失英文。
- 中英文标题属于同一张卡片和同一草稿／发布版本。改名或补英文不创建另一张卡，不改变稳定卡片引用、收藏及学习记录。
- 发布前的英文修改只进入候选稿；小程序继续读取旧发布版本，确认发布后再整体切换两种标题及对应内容。

### 15.3 第二组：场景对话

提供两个入口：“粘贴／编辑对话”“从DOCX带入”。

- 对话按一组一行维护：人物、英文台词、中文台词。
- 可添加、删除和调整组顺序；至少一组完整对话才能发布。
- 粘贴区域按固定示例整理，生成可编辑预览；无法确定中英文配对时标记“请确认对应关系”，不调用AI翻译。
- DOCX只带入资料，先显示变化供确认，不覆盖未保存输入；可选择取消，或明确选择替换对话及对应附加资料。
- 对话更改导致原词汇定位失效时，标记对应词汇“请重新确认高亮位置”；旧发布版本不受影响。
- 删除已有来源句前说明其关联词汇将待核对，不能遗留指向不存在句子的高亮。
- 一句较长台词可完整换行，不按显示行数自动拆句，不要求音频时间信息。

### 15.4 第三组：重点词汇

每条词汇显示：英文、本句中文释义（选填）、音标（选填）、对应原句与高亮预览；右侧提供添加／删除及顺序调整。发音试听为轻量喇叭，调用同一腾讯云服务。

操作顺序：

1. 填写英文，按需补充本句释义与音标。
2. 系统在已录入英文对话中寻找完整词／短语候选；不以短字符串命中其他单词的一部分。
3. 唯一候选显示原句及高亮供核对；进入最终预览并确认发布即确认该唯一候选，不要求重复点多次。
4. 多处候选展开可读原句，管理员选择具体出现位置；同一句有多处时也展示可点击片段。
5. 未找到时显示“未找到对应位置，请修改词汇，或在原句中选择片段”；允许词典原形绑定实际变形，如buy绑定bought，但需管理员明确选择。
6. 本期每条词汇绑定一个明确来源片段；需要不同原句或意思时新建另一条词汇，不批量高亮所有同名词。
7. 重叠高亮提示选择正确的非冲突范围，不静默覆盖另一个条目。
8. 确认后展示最终原句和本句释义；系统维护内部位置，管理员不填写ID或字符偏移。

词汇至少一条。英文、有效来源与高亮位置缺失时可保存但不可发布；本句释义及音标均选填，缺失不阻止发布，前端只隐藏缺失内容及其占位，不隐藏单词。系统不自动查通用词义回填。

### 15.5 第四组：语块（选填）

初始仅显示“语块（选填）”“添加语块”和“没有可直接跳过”。添加后每行只有英文、中文释义及顺序／删除操作。

- 没有条目是正常完整状态，不报错、不要求“确认无语块”。
- 添加了空白行且未填任何内容，可保存时自动移除；填写了一半则标出需补充或删除。
- 拟发布语块必须中英文完整。
- 不设置语块配图、发音、来源定位或收藏字段。
- 删除最后一条后，前端预览整区消失，不预留空间。

### 15.6 保存、离开与冲突

| 情况 | 处理 |
|---|---|
| 保存草稿成功 | 停留A03，更新已保存状态 |
| 保存失败 | 保留文本及成功上传的文件引用，提示重试；不声称已保存 |
| 未保存离开 | A03-P2：“继续编辑／保存后离开／放弃本次修改” |
| 保存后离开失败 | 停留编辑页，保留输入；不执行后续跳转 |
| 放弃本次修改 | 仅放弃本次未保存变更，保留上次已保存草稿与线上版本 |
| 另一窗口已更新 | 提示资料已变化，停止覆盖；保留本页输入供核对，刷新当前保存版本后再确认 |
| 上传仍进行时保存或发布 | 明确提示等待上传完成或取消相应上传，不保存悬空素材引用 |

### 15.7 文件真实上传进度

#### 15.7.1 入口与展示

适用于现有卡片编辑及批量导入中的文件上传控件。上传文件后，在文件所在位置显示名称、进度条、百分比和当前状态，不要求管理员切换到其他管理页查看。

| 状态 | 展示及操作 |
|---|---|
| 等待上传 | 显示文件名及“等待上传”，不显示已经开始的假进度 |
| 上传中 | 显示真实传输进度条和百分比 |
| 上传完成待处理 | 传输达到100%，显示“上传完成，等待处理” |
| 校验／解析中 | 显示“上传完成，正在处理”，可补充具体校验／解析阶段；不伪造处理百分比 |
| 处理完成 | 显示文件处理成功；进入现有核对或后续操作，不等同于卡片已经发布 |
| 失败 | 显示文件名、失败原因及“重试” |

#### 15.7.2 进度与成功判断

- 上传百分比依据本文件实际已传字节／总字节计算，不使用定时动画模拟进度。
- 暂时无法取得可计算长度时显示“正在上传”；取得真实长度后再显示百分比，不编造数字。
- 传输100%仅表示文件传输完成，校验或解析尚未结束时不能显示导入成功。
- 上传成功、文件处理成功、保存草稿成功和发布成功是不同结果，分别按实际阶段提示。
- 上传选择数量与关联方式统一按第17章执行：保留单ZIP并支持多ZIP队列；本节的字节进度规则不改变素材归属。

#### 15.7.3 失败与离开

- 重试仅针对失败文件或失败阶段，保留其他已成功上传的资料，不要求全部重传。
- 上传未完成时不能保存悬空文件引用或发布；提示等待上传完成或按现有上传流程处理。
- 离开页面后，不把本地尚未完成的传输标为成功。返回时依据服务端已确认状态恢复现有可恢复资料。

### 15.8 完整音频上传事实、时长与试听状态

#### 15.8.1 入口与状态

适用于现有卡片编辑、导入核对及查看上传效果的完整音频区域。依据真实文件状态展示，不能仅凭播放器初始时间判断是否上传成功。

| 状态 | 页面显示 | 允许操作 |
|---|---|---|
| 未上传 | “未上传完整音频”，不展示可用播放器 | 编辑或核对页通过现有入口补充；只读预览不直接修改 |
| 上传中 | 文件名、实际进度及“上传中” | 不播放尚未完成的新文件 |
| 校验中 | “上传完成，正在校验音频” | 不把传输100%当作可试听 |
| 已上传且时长读取中 | “已上传”、文件名、“时长读取中” | 等待真实时长，保留上传成功事实 |
| 已上传且可试听 | “已上传”、文件名、真实总时长及播放器 | 点击播放／暂停，试听完整音频 |
| 上传／校验失败 | 具体失败原因 | 编辑或核对页重试上传或重新选择文件 |
| 已上传但读取失败 | “已上传”“音频读取失败”及原因 | 提供读取重试，不误报文件缺失 |

#### 15.8.2 播放与版本

- 不以 `0:00 / 0:00` 作为上传成功依据；元数据未就绪时显示读取状态，就绪后才显示真实总时长。当前播放位置0:00不代表文件未上传。
- 完整音频区域使用一个主播放器，播放状态和进度保持一致，避免独立按钮互相冲突。音频显示“已上传”仅确认原文件传输事实；仍在兼容处理或播放副本未就绪时，不开放新文件试听或发布，具体处理状态见第15.9节。
- 草稿效果读取对应草稿音频，已发布效果读取当前发布音频，不能混用版本。
- 关闭预览、切换卡片或离开页面停止该音频播放，不自动开始播放下一张。
- 更换音频时，新文件上传及校验成功后才替换当前编辑稿引用；失败时保留原有效音频及已保存资料，不能把旧文件清空。
- 音频上传成功不等于草稿保存或发布成功；已发布音频只有在对应修改确认发布后才切换。

### 15.9 四类音频输入与统一播放副本

#### 15.9.1 接收范围

本次明确支持管理员已有的MP3、M4A、WAV、AAC四种完整对话音频输入，覆盖单卡编辑上传、ZIP内解析和DOCX配套资料上传，前后端校验范围一致。

| 输入格式 | 常用后缀 | 要求 |
|---|---|---|
| MP3 | .mp3 | 校验真实格式与可解码性，合格播放文件可复用 |
| M4A | .m4a | 检查容器内实际音频编码，不以后缀代表编码已兼容 |
| WAV | .wav | 检查可解码内容，不因文件较大而误判为无效格式；仍受统一大小限制 |
| AAC | .aac | 校验实际音频数据与可解码性 |

- 后缀大小写均可识别。文件选择控件、服务端接收白名单、ZIP扫描、帮助文案和下载示例同步支持这四类，不能单卡可传而ZIP只认MP3。
- 每卡一份完整对话音频，文件可以是“完整音频”加支持的后缀；包内只有一个合法候选时按同目录关系预选供核对，不强迫管理员改扩展名。
- 不要求管理员把同一音频另存多种格式，也不以“把后缀改成.mp3”充当转换。
- 空文件、损坏、伪造后缀、加密／受保护或无法解码的文件提示具体原因，不只显示“上传失败”。
- 此处的四种格式为本轮明确接收范围，不把“多格式”写成任意格式均保证支持；其他格式给出清晰的不支持提示。

#### 15.9.2 上传格式与播放格式分离

支持上传不等于能在所有客户端直接播放。服务端保留原始文件及真实格式，校验后为非合格播放格式生成MP3完整播放副本；已符合播放要求的MP3可直接复用。后台试听和小程序统一取得经过校验的播放资源，管理员无需自行转码。

- 兼容处理只改变音频编码／封装，不重写、重录、翻译或裁切原对话，不生成单词音频、语块音频或逐句切片。
- 原文件和播放副本绑定同一卡片候选版本，记录来源和处理状态；原始文件名与格式供管理员识别，播放副本真实格式不得靠错误后缀伪装。
- 处理后检查音频可解码、时长有效且内容完整；不得丢句、截断或出现明显失真。转换失败保留源文件及旧有效音频，仅该卡标待处理，不影响其他合格卡。
- 替换音频只有新文件上传、校验及必要转换全部成功后才切换当前编辑稿引用；保存失败或转换失败不清空旧文件，已发布用户仍使用旧发布版，确认发布后再整体更新。
- 播放地址、响应类型与资源实际格式一致。后台试听通过不代替小程序iOS、Android真机验证；实现需完成两端实际播放、时长和拖动验证。

#### 15.9.3 状态和试听

| 状态 | 页面反馈 |
|---|---|
| 未上传 | “未上传完整音频”，提供原有补充入口 |
| 上传中 | 显示文件名及真实进度 |
| 校验／兼容处理中 | “已上传，正在校验／处理音频”，新文件暂不开放试听 |
| 处理失败 | 展示具体失败阶段、原因及重试；保留旧有效音频 |
| 已就绪 | “已上传”、原文件名／原格式、真实总时长及完整音频播放器 |
| 播放资源读取中 | 显示读取状态，不把0:00/0:00当作处理成功 |
| 已就绪但读取失败 | 保留已上传事实，提示读取失败及重试，不把文件误标缺失 |

- 不自动播放；管理员主动试听完整内容。关闭预览、切换卡片或离开页面停止试听。
- 草稿预览和已发布效果分别读取对应版本音频；不能把新上传未发布音频提前给用户。
- 新卡发布及更新发布需要本候选版有可用的播放资源；待转换、失败或缺失只能保存草稿，不能提前发布。旧发布版本不因新候选处理失败而下线。

## 16. A03-P1 预览与A02-P2批量发布

### 16.1 单卡预览并发布

点击“预览并发布”先保存当前输入为候选草稿，再校验双标题、完整音频播放资源及其他发布资料；保存失败不进入发布。校验问题直接定位原字段并保留草稿。

A03进入的草稿预览模式完整展示U03布局，顶部标注“预览，尚未发布”。允许大图与音频试听；收藏和完成按钮只显示禁用的“收藏（预览）／已完成学习（预览）”，不可写入真实收藏、完成或打卡；译文默认收起，可展开核对。

后台各只读预览（A03-P1草稿／发布效果、A06-P1及批量预览）复用内容排版而不启用新增用户业务：分享、提交反馈、学习开始写入和来源学习队列隐藏或明确禁用；中央查词只作禁用示例，不调用用户正文词典接口。既有管理员受控词汇及完整音频试听、大图和译文核对保留，不将候选草稿提交给只允许当前发布正文的用户接口。

底部“返回修改／确认发布”。返回保留编辑位置；确认后提交预览对应候选版本，处理中防重复点击。

| 发布结果 | 处理 |
|---|---|
| 成功 | 提示“已发布，可在学习列表查看”，回A02并定位卡片 |
| 校验失败 | 保留草稿，关闭或返回修改并定位问题 |
| 网络失败／结果未知 | 查询最终状态，幂等重试，不重复生成发布记录 |
| 预览后内容被改动 | 旧预览失效，要求重新预览，不用旧确认发布新资料 |
| 发布失败 | 保留原线上版本与候选稿，可重试 |

A02“查看效果”复用A03-P1的已发布只读模式：顶部标注“当前发布效果”，只读取当前发布版本的中英文标题、图片、对话与就绪音频，底部仅“关闭”，不显示“返回修改／确认发布”。关闭回A02原筛选与位置；草稿不会替代发布内容。两种模式均可看图试听及展开译文，均不写真实收藏、完成或打卡，模式由入口确定。

### 16.2 批量发布

1. A02选中卡片后点击“批量发布”，系统检查各自最新候选稿。
2. A02-P2显示“可发布N张、待补充M张、无需发布K张”，列出名称和原因。
3. 可发布集合提供逐卡切换预览，布局与单卡相同；不新增独立抽样中心，不要求打开其他管理页。
4. 管理员明确确认选中集合已核对。主按钮显示“确认发布N张”；N为0时禁用。
5. 只提交已选且合格的集合，待补充项目保留草稿，不被顺带发布。
6. 发布过程中显示已成功／处理中／失败数量。每张原子发布，部分失败不回滚成功项。
7. 结果列出具体卡片；“重试失败项”只处理仍合格且未成功的项目。若期间版本变化，先重新校验与预览。
8. 关闭结果回原A02，状态刷新；后台处理已接受的操作有持久记录，可返回查看，不能因关闭覆盖层丢失最终结果。

## 17. A04 批量导入：同页三步

### 17.1 公共布局

顶部标题“批量导入”，下方固定三步：1上传资料 → 2核对卡片 → 3保存草稿。页面当前步骤高亮，返回上一步保留已上传资料和修改；数据变化会使受影响的后续确认失效。

界面始终显示“导入只保存草稿，发布需在卡片管理中确认”。系统处理阶段使用“正在读取资料／正在保存”等短文案，不要求看任务码、模型日志或长ID。

核对步骤的改动自动保存为本次导入暂存，显示“保存中／已保存”；暂存不是卡片库草稿，第三步确认后才创建或更新卡片草稿。暂存保存失败保留输入、提示重试，未保存成功前不能继续下一步；离页时说明未保存部分，避免声称可以恢复尚未落盘的修改。

### 17.2 第一步：上传资料

先显示“下载填写示例”，再提供两种上传方式，一批只选一种：

| 方式 | 管理员提交 | 下一步 |
|---|---|---|
| 上传ZIP | 一次选择、拖拽或继续添加多个ZIP；每包可含一张或多张卡 | 逐包处理全部卡片，合并进入同一核对列表；保留单ZIP方式 |
| 上传DOCX及配套资料 | 一份或多份固定模板DOCX，可多篇；另选图片与完整音频 | 按明确名称产生对应候选，进入核对确认 |

页面说明每张卡片需要“中文标题、英文标题、场景图、完整音频、中英文对话、词汇；本句释义、音标及语块选填”。两种方式的音频输入均为MP3／M4A／WAV／AAC，规则一致。不出现学习模块、内容类型、权益范围、OCR或供应商选择。

- 上传过程有真实进度与取消入口；失败只重传失败文件，保留其余成功资料。
- 没有读到任何可恢复卡片时停留本步，显示文件及修正建议。
- 文本可读但图片／音频缺失时可进入第二步，标记待补充。
- ZIP内未引用额外文件列为“未使用文件”，不静默绑定。
- 返回卡片管理前，已建立且成功保存的批次和核对结果保留；A04再次进入按17.6查询真实可恢复批次，符合条件才显示“继续处理”，不新增任务中心。

### 17.3 第二步：核对卡片

顶部显示总数及“资料完整／待补充／重复／无法读取”数量；列表每行显示勾选框、中英文标题、缩略图、来源ZIP／卡片目录、状态和问题摘要；包数与卡片数分别统计。点击行展开同页详情，不反复跳转。

展开内容按照A03四组顺序展示，复用同一编辑规则。管理员能直接选择正确图片、试听音频、调整对话、修正词汇和可选语块。

| 状态 | 含义 | 默认选择／允许动作 |
|---|---|---|
| 资料完整 | 可读取且结构完整，仍需预览确认 | 默认选中，可查看或取消选择 |
| 待补充 | 有可恢复资料，但缺双标题、必需素材、就绪音频或高亮确认 | 默认选中，可补充或保存不完整草稿 |
| 重复 | 已确认是同一导入对象及相同资料 | 默认跳过，不重复新建 |
| 无法读取 | 没有可保存结构，或存在不能接受的包错误 | 不可选，修正文件再读取 |

- 不明确的素材候选显示文件名、图片与试听，让管理员选择；无对应关系时不默认绑定。
- 更新已有卡片必须明确选择目标，并展开A04-P1前后差异；不同卡片不能只因名称相同自动合并。
- 正文或素材变更会重新检查受影响词汇位置及完整性。
- 返回第一步补文件保留已有录入；成功补充后仅重新校验相关卡片。
- 第二步切换查看卡片不丢修改。勾选卡片代表本次准备保存的范围，不等于确认发布。
- 下一步按钮“核对完成，下一步”；没有任何可保存选中项时禁用并说明原因。

### 17.4 第三步：保存草稿与结果

确认区显示“将保存N张草稿，其中M张仍待补充”，列出中英文标题、来源ZIP／目录、完整性和“新增／更新草稿”；重复项、排除项和无法读取项单独统计。

- 主按钮“确认保存草稿”，次按钮“返回核对”；不出现“立即上线”。
- 点击后逐卡保存；重复点击复用同一操作，不新建重复卡片或版本。
- 保存完成后在本步下方显示“成功N、失败M、跳过K、排除L”，不跳独立成功页。
- 已接受的保存任务可在离页后恢复结果，不能显示虚假的全部成功。
- 结果入口：“查看本次卡片”→带本次导入筛选的A02；“补充资料”→对应A03；“重试失败项”→本页必要阶段。
- 成功项不随失败重试再次执行；离开后已有草稿不丢失。
- 全部保存失败时保留核对结果，可重试或返回修改。
- 返回核对后做了变更，第三步重新显示当前范围，旧确认不能继续提交新内容。

### 17.5 多ZIP队列、统一核对及失败恢复

#### 17.5.1 上传入口与文件队列

在现有“批量导入→上传ZIP”入口支持一次选择多个ZIP，也支持拖拽多个ZIP和继续添加ZIP；保留单ZIP上传及原有DOCX配套资料方式。

- 文件队列显示每个ZIP的文件名、大小、状态与上传进度；上传前可移除，上传中可取消该文件。
- 每个ZIP可以包含一张或多张卡片。后端逐包读取全部合格卡片文件夹，不能只处理第一个ZIP或第一张卡。
- 采用受控并发，不能因多选而无上限同时传输／解析；文件数量和大小限制沿用服务端部署配置，选择前可见，不要求管理员填写技术参数。
- 本次不增加直接上传多个本地文件夹的入口。多个ZIP只是上传方式扩展，卡片模板及资料归属仍按文件夹明确关联。

结构示例：

~~~text
戏剧与阅读.zip
├── 为戏剧社挑一个剧本/
│   ├── 内容.docx
│   ├── 场景图.png
│   └── 完整音频.m4a
└── 写一篇有证据的书评/
    ├── 内容.docx
    ├── 场景图.png
    └── 完整音频.wav

烧烤场景.zip
└── 准备一桌烧烤食材/
    ├── 内容.docx
    ├── 场景图.png
    └── 完整音频.aac
~~~

示例中的内容DOCX均包含第18.2.1节规定的中文一级标题和英文标题元信息。每张卡只需一份完整音频，不要求同时提供四种格式。

#### 17.5.2 对应 进度与统一核对

- 同一包内同一卡片文件夹的DOCX、场景图、完整音频形成明确关联；不同ZIP中即使文件夹、文件同名，也按包实例与相对路径隔离，不混配、不覆盖。
- 单个文件传输进度根据实际字节计算；传输100%后显示校验／解析中，不提前显示已导入或已发布。
- 多包解析结果合并到同一个核对列表，显示来源ZIP、卡片目录、中英文标题、缩略图、资料完整性和问题原因。
- 包数和卡片数分别统计；一包三卡要显示一包、三卡，不混用数量。
- 可读取但缺图片、英文标题或完整音频时标待补充，可保存不完整草稿，补齐后再发布；一个文件夹存在多个音频候选时让管理员选择，不猜配。
- 重复同一资料提示跳过；同名不等于重复。更新已有卡片须明确目标和差异，不能静默覆盖。

#### 17.5.3 部分失败 取消与返回

- 一个ZIP、一个卡片或一个音频转换失败，不影响其他合格资料继续核对和保存。
- 上传失败可只重传该ZIP；解析或音频处理失败可只重试对应失败阶段。已成功创建的草稿不重复新建。
- 取消尚在传输的ZIP只影响该文件；服务器已接受解析时，显示真实阶段，查询结果后处理，不假称整包从未上传。
- 未完成／失败／取消项目明确列出，不静默忽略。仍上传中的文件须等待完成或明确取消后再进入核对；解析失败但已有其他可恢复卡时可继续核对。
- 返回上一步、切换卡片时保留成功上传、核对输入及中英文标题；无法恢复的本地未完成传输明确提示，不假称已保存。
- 结果显示成功、失败、跳过数量及名称；“重试失败项”只作用于原失败集合。结果未知时先查询服务端，不直接重建。
- 流程保持“上传资料→核对卡片→保存草稿→卡片管理→预览并确认发布”。上传和导入均不自动发布。

### 17.6 可恢复批次与继续处理

A04先查询当前管理员可访问、服务端已保存且仍可恢复的未完成批次。零批次隐藏“继续处理”，保留正常上传入口；请求失败显示查询失败和重试，不冒称不存在批次。仅本地选择文件或未成功落盘的输入不算可恢复。

一个或多个批次通过A04-P2列出文件名／来源包、上传或最近更新时间、真实阶段及必要问题摘要；管理员明确选择后恢复。多个批次不静默默认最近批，不展示“其他最近导入”。这个待处理选择是未完成业务恢复，不是历史最近导入列表。

恢复对应上传／解析／核对暂存／保存结果及成功资料，只重试适用失败阶段；服务端校验批次所有权与状态，过期或已处理完的批次说明并刷新待处理集合，不打开错误批次、不重复创建已存草稿。未完成上传所需本地原文件不可恢复时明确要求重选失败文件，不能伪称文件已上传。

当前批次保存后的“查看本次卡片”“补充资料”“重试失败项”继续保留，不能因删除最近导入展示而删掉结果去向。导入仍只存草稿，确认发布在A02／A03完成。

## 18. 批量资料模板与素材对应

### 18.1 固定ZIP结构

“下载填写示例”提供包含双标题元信息和四类音频说明的资料包规范。一次可上传多个ZIP，每包采用“一张卡片一个文件夹”，管理员不需要填写Excel中的技术ID。示例及界面帮助在实际开发时一并更新，本轮不修改下载文件或接口。

~~~text
场景资料.zip
├── 咖啡店点单/
│   ├── 内容.docx
│   ├── 场景图.jpg
│   └── 完整音频.mp3
└── 问路/
    ├── 内容.docx
    ├── 场景图.png
    └── 完整音频.m4a
~~~

- 同一包实例内，同一卡片目录的内容、图片和音频形成明确关联；不同ZIP即使目录／文件同名也隔离，不混配或覆盖。文件夹名只帮助识别，不作为稳定卡片ID。
- 每个卡片文件夹只应有一份内容DOCX、一张场景图、一份完整音频，且该DOCX只能包含一张卡片。缺失进入待补充，多候选须管理员选择。
- ZIP中某份DOCX含多个卡片一级标题时，该文件夹标记“无法读取”，提示“一个文件夹应只有一张卡片，请拆分文件夹，或改用上传DOCX及配套资料”。不自动生成多张共用该文件夹素材的卡片；其他合格文件夹可继续核对。
- 本期不接收词汇音频、词汇图、切片文件和语块图片；上传包内出现时列为未使用资料，不绑定到学习字段。只提供场景图和完整对话音频的素材入口。
- 原始文件可保留中文名；管理员看到文件名和预览，不要求手填服务器路径。
- ZIP解包禁止绝对路径、越级路径、符号链接逃逸及同路径覆盖；只解析允许的资料，不执行文件。规模限制由部署配置统一校验，错误说明到具体文件。
- 本版使用新模板，不承诺继续运行旧版完整内容包的全部导入分支。旧资料需转换为本版字段或通过DOCX入口核对，不能将旧模块模板自动当新卡片发布。

### 18.2 DOCX内容示例

每张卡片以独立一级标题开始，并有固定小标题“场景对话／重点词汇／语块”。“上传DOCX及配套资料”方式允许一份DOCX含多张卡片，遇下一个一级标题分卡；ZIP方式每个文件夹的DOCX必须恰好一张卡片，不能使用多卡DOCX。

**一级标题：在咖啡店点单**

英文标题：Ordering at a Coffee Shop（正文元信息，不是第二个一级标题）

**场景对话**

| 人物 | 英文 | 中文 |
|---|---|---|
| Ivy | Could I get a latte, please? | 请给我一杯拿铁。 |
| Barista | Sure. What size would you like? | 好的。您要多大杯？ |

**重点词汇**

| 词汇 | 本句释义（选填） | 音标（选填） | 对应英文原句（建议填写） |
|---|---|---|---|
| latte | 拿铁咖啡 | 可填写经核对的音标，也可留空 | Could I get a latte, please? |
| size | 杯型；容量大小 | 可留空 | What size would you like? |

**语块（选填）**

| 英文 | 中文释义 |
|---|---|
| Could I get ...? | 请给我……，好吗？ |

- 没有语块可省略整个小标题和表格，不需要填“无”。
- DOCX中的英文和中文由管理员提供；解析只读取结构、配对与原顺序，不自动改写或补译。
- 对应原句可帮助定位。唯一匹配可形成预选候选；重复或无法定位仍须第二步人工确认。
- 没有合法分篇标题、语言配对不清、字段缺失时提示修改，不靠任意空行猜分篇。
- 单卡编辑导入的DOCX如果含多张卡片，提示改用批量导入，不静默只取第一张。
- 图片可出现在DOCX示例说明中，但正式场景图片通过独立图片文件提供；不把嵌入截图做OCR或当正文。
- 本段是开发需提供的模板规范；本次文档交付不代表模板下载接口或示例文件已在后台上线。

### 18.2.1 双标题元信息解析与旧模板兼容

ZIP内继续一张卡片一个文件夹，每文件夹一份内容DOCX。新DOCX在唯一的卡片一级标题下，增加固定元信息“英文标题：”。一级标题仍作为中文标题，避免两个一级标题被误识别成两张卡。

模板示例：

~~~text
一级标题：为戏剧社挑一个剧本
英文标题：Choosing a Play for Drama Club

二级标题：场景对话
人物｜英文｜中文
……

二级标题：重点词汇
词汇｜本句释义（选填）｜音标（选填）｜对应英文原句（建议填写）
……

二级标题：语块
英文｜中文释义
……
~~~

- “英文标题：”使用正文段落，不使用第二个一级标题；允许中文或英文冒号，标签后内容读取为该卡英文标题，去除首尾空白。
- 每张卡的英文标题只读取当前一级标题范围内、首个内容二级标题之前的元信息，不把对话英文或词汇当标题。
- 缺失或空值标“待补充英文标题”；多个相互冲突的英文标题值标问题并要求核对，不任取一个覆盖。
- 旧DOCX只有中文一级标题时仍可解析、核对并保存草稿；不因模板升级整包拒绝。英文须在核对或编辑页补齐后才可发布。
- 一份独立DOCX包含多张卡时，每张一级标题各配自己的英文标题；ZIP内单份DOCX仍只允许一张卡。
- “下载填写示例”和页面帮助同步更新。名称元信息不改变原有对话、译文、词汇音标及语块表格结构，也不擅改原英文对话与现有音频。

### 18.3 独立DOCX与素材对应

- 优先识别明确的卡片名称与同名素材，例如“咖啡店点单.docx／咖啡店点单.jpg／咖啡店点单.mp3”。
- 多篇DOCX时以每篇一级标题对应素材名；唯一完整同名只能作为待核对候选，最终在第二步预览确认。
- 重名、多图、多音频、名称不一致时显示“请选择对应图片／音频”，不按上传顺序、模糊相似度或文件序号猜配。
- 选择器提供图片缩略图、音频文件名及试听；已选素材明确显示所属卡片，避免误选。
- 系统内部生成稳定卡片、句子和词汇引用；映射由系统保存，导入重试和后续编辑复用，不让管理员手填。
- 更新已有卡片可通过已有可靠导出引用／已确认映射定位；没有可靠引用时只能提出候选，由管理员按名称、缩略图及正文选择目标。
- 名称相同不等于同一张卡片，文件名改变不等于必须新建。确认更新之前展示目标卡片和差异。
- 同一完整对象及相同规范化资料／素材哈希重复提交为跳过；疑似重复但无法确认对象时请求核对，不擅自合并。
- 更新只写候选草稿；涉及发布和收藏的效果仍在确认发布后发生。

### 18.4 常见问题与中文反馈

| 问题 | 页面提示与处理 |
|---|---|
| 没有图片 | “缺少场景图片，可现在补充，也可先保存草稿” |
| 没有完整音频 | “缺少完整音频，发布前需要上传” |
| 图片／音频无法解码 | 定位文件，提供更换；不把损坏文件当已上传成功 |
| 词汇缺本句释义或音标 | 正常选填状态，不阻止发布；仅隐藏缺项及其占位，不隐藏英文或发音入口 |
| 缺英文标题／元信息冲突 | 标待补充或待核对，允许存草稿；不从中文、文件名、图片或对话猜英文 |
| 多包同名目录／文件 | 按包实例与相对路径隔离，逐卡核对，不同名合并或覆盖 |
| 音频兼容处理中／失败 | 保留原文件和旧有效音频；就绪前只存草稿，失败只重试相应阶段 |
| 词汇多处出现 | 展开原句让管理员选择，不提示输入ID |
| 无语块 | 正常，无提示、无额外确认 |
| DOCX无法读取 | 列文件名和原因，重新上传；不生成假正文 |
| 同名不同资料 | 让管理员选择新增或更新目标，并展示差异 |
| 已确认重复资料 | 提示“资料已存在，本次跳过”，保留原内容 |
| ZIP内有额外素材 | 列为未使用文件，可手动选择或保持未使用 |
| 部分资料失败 | 保存可恢复资料，标出失败项目，允许只重试失败项 |
| 超出上传限制 | 在选择前与失败位置说明当前限制和处理方式；不损失其他资料 |

## 19. 发布、版本、下线、删除与排序

### 19.1 状态与前端效果

| 操作 | 后台结果 | 前端效果 |
|---|---|---|
| 新建／保存草稿 | 稳定卡片与草稿 | 不出现，不写用户数据 |
| 首次发布 | 原子启用完整版本 | 学习列表出现，用户可学与完成 |
| 编辑已发布卡 | 另存候选稿，线上不动 | 继续原发布内容与完成状态 |
| 发布更新 | 整体切换中英文标题、正文、译文、图、就绪完整音频、词汇 | 下次进入／刷新读新版，不重置完成或收藏 |
| 下线 | 保留管理与版本引用 | 列表移除，历史／收藏不可用，学习成绩保留 |
| 重新发布 | 核对后启用 | 重新可学；原收藏、已学标记保留 |
| 删除 | 业务删除并停止所有普通访问，主列表移除 | 不能学习，历史摘要与总成绩保留 |
| 排序 | 保存展示顺序 | U01刷新生效，不改收藏或学习记录顺序 |

### 19.2 发布校验

新卡发布及已有卡片新版本发布须同时满足：中文标题与英文标题完整、场景图有效、完整对话音频上传及校验／必要兼容处理完成且播放资源就绪、至少一组有效人物及完整中英文对话、至少一条英文词汇及有效来源／高亮位置（本句释义、音标选填）、已有语块中英文完整、无冲突及当前预览确认。历史已发布缺英文卡不被批量下线，继续使用原版本，补录重发按新校验执行。

- 中文译文虽前端默认收起，后台仍必须完整提供，不能因默认不看而缺失。
- 不要求词汇音频文件，词汇区没有上传按钮，批量模板也没有该字段。
- 不要求语块、本句释义、音标、词汇图、时间点、切片、AI义项或权益配置。
- 草稿允许不完整；批量按单卡判断，不被其他失败卡片整批阻塞。

### 19.3 一致性与幂等

- 详情一次获取同版本全部资料，个人收藏／完成／当日状态来自真实查询；不混正文和音频版本。
- 改标题、正文或素材使相关预览确认失效，来源变化还须重新核对高亮后发布。
- 每卡发布原子执行，失败保留原线上版；批量部分成功不回滚。
- 保存、导入、发布、下线、删除、收藏及完成均幂等，超时先查真实结果。
- 资源请求发现版本失效时停止失效音频并整体刷新，不在播放中静默换词义或只换音频。
- 下线／删除生效后拒绝新正文、音频、完成和新增收藏请求；已有成绩和有效日期不回退。
- 当前页面收到停用结果进入U05；大图也关闭，不用缓存恢复全文。
- 缩略图／安全名称可用于本人收藏和已学历史识别；不因此开放已删除卡片全文。
- 资源清理保护正在发布／草稿及必要历史摘要引用，不因删卡误删其他卡片复用的素材或共享词汇发音缓存。
- 本期没有历史全文浏览、回收站恢复或手工版本回退界面。

### 20.2 唯一性

- 同一AppID＋服务端校验的OpenID只对应一个稳定用户ID；并发或重复登录不重建账号和成绩；不接受客户端自报身份作为可信键。

- 累计完成按用户＋稳定卡片，日学习按用户＋卡片＋日期，打卡按用户＋日期。
- 同一卡片换版本、改名和改图不改变上述唯一键。
- 本次队列与开始标记不替代完成唯一键；反馈首次提交、补充、回复及状态动作按各自操作防重复，已读仅推进实际显示过的事件，不越过并发新回复。

## 32. 后续需求维护与版本流程

### 32.1 文件职责与版本

完整主需求是当前已合并的开发基线；[需求变更清单与记录](需求变更记录.md)沿用原文件名，统一登记所有修改；[需求同步检查表](需求同步检查表.md)记录设计及开发的真实完成情况。每个新修改先生成“[小需求变更单](小需求变更单/模板-小需求变更单.md)”，文件名使用“CHG-连续编号-简短主题.md”，放入“小需求变更单”目录。

3. 在变更清单登记同一编号、小单链接、修改摘要、影响页面／章节、状态、确认依据及合并目标／结果。编号不重用，不删除历史记录。
4. 用户明确下达的修改要求可以直接记为“已确认待合并”；要求先预览／验收、仍在讨论的方案记“待确认”。需求确认与设计验收分别记录，不重复索要已有确认。

A09展示同一时间线、受控截图、来源摘要、回复输入、开始处理／要求补充／标记已处理动作。要求补充及标记已处理需有对应说明或回复，失败保留输入且状态不先变。回复及状态写入保留管理员、事件、服务器时间和幂等结果，不允许用页面关闭冒充处理完成。

### 33.6 权限、失败与历史

用户接口检查本人反馈所有权，不能通过猜ID读取或补充他人记录；管理员使用独立登录鉴权。用户或管理员会话失效时停止提交，重新登录后先重查结果，不自动提交保留输入。

卡片下线／删除不删除既有反馈及时间线；保存提交时安全标题，当前来源标为暂不可用／已删除，不展示旧全文或恢复失效音频。账号资料中的通用反馈仍可提交；场景已经失效时不以旧详情继续创建有完整内容的来源。

反馈列表空、读取失败、截图上传失败、提交结果未知、回复失败、状态冲突、未读清除失败分别反馈并允许适用重试。确认需求不代表已接入真实截图存储、内容安全或后台服务。

## 34. 页面分享与登录后目标恢复

### 34.1 范围与分享内容

仅U01学习页和U03场景详情开放微信好友、群及朋友圈原生分享；收藏、学习记录、账号资料与反馈等个人页面不提供分享入口。用户主动发起分享，不增加图片海报制作或额外分享配置页。

| 页面 | 标题与图片 | 接收目标 |
|---|---|---|
| U01 | 固定标题“句芽英语｜在真实场景里学英语”，统一品牌分享图 | U01公共学习入口，登录后展示接收者本人数据 |
| U03 | 当前已发布中文标题及英文标题，复用当前场景图适配分享封面 | 相同稳定卡片的当前有效发布详情 |
| 历史缺英文卡 | 仅已有中文，不假造英文或空行 | 原卡，不另建卡片 |

微信好友／群分享按title、path、imageUrl承载，朋友圈按title、query、imageUrl承载；不虚构原生独立描述字段。好友／群封面按5:4、朋友圈封面按1:1适配，保持内容可辨识，不裁成误导性内容；只做分享展示副本，不改变原场景图。已有双标题或场景图更新后按当前发布版本生成分享展示，草稿及未发布标题不泄露。

参考：[微信官方接口定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.page.d.ts)。分享文案采用固定模板及已有字段，不让管理员逐卡重复填写；渠道标题被平台截断时完整双标题仍在目标详情显示，不更改正式标题。

### 34.2 身份与目标恢复

分享参数只携带目标类型及稳定卡片引用，不传发送者会话、个人统计、联系方式、收藏或反馈ID；用户打开后查到的是接收者自己的收藏／完成状态。

好友／群及完整小程序入口：无有效业务会话 → U00默认未勾选 → 主动同意并登录 → 服务端稳定身份与会话 → 重查目标当前发布状态 → 原分享U03；有效会话校验复用后直达，不反复要求登录。U01分享登录后回U01。

登录取消或失败留U00且保留安全目标，明确重试后成功再返回；不先返回完整正文、音频或可写学习操作。登录响应丢失沿用稳定身份幂等，不能因分享重复创建账号。

### 34.3 朋友圈单页入口

兼容微信朋友圈单页模式：显示当前分享的安全标题、适配分享图及“打开小程序后登录学习”引导，不在单页请求完整学习正文、音频、个人资料或发起完成／收藏。通过平台提供的打开完整小程序入口承接，保留稳定目标，再按34.2登录恢复。

参考：[腾讯官方单页模式说明](https://cloud.tencent.com/document/product/1301/107818)。不将单页模式误写为完整小程序，或在受限入口伪造已成功登录。实际AppID、微信版本及iOS／Android入口需真实接入时验证；不支持朋友圈能力时保留可用好友／群方式及明确提示，不伪造成功。

### 34.4 完成、返回与失效

分享单卡没有来源列表队列。完成成功留在U03，显示今日状态及“前往学习页”；再次阅读、查词、播放或收藏不重复计数。顶部返回无有效来源时回U01，不能返回分享者的页面或列表。

已下线／删除目标进入U05，仅安全摘要和“返回学习页”；目标参数无效说明无法找到内容并提供U01。分享摘要不作为正文访问凭证；已收藏的有效关系及原学习成绩仍按总控保留。分享失败或取消不展示虚假完成，不影响本次学习及个人数据。
