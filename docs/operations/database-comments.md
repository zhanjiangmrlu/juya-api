# 数据库中文用途注释

模型中的表注释及字段 `comment` 是后续建库的说明来源；0025迁移冻结本次说明，不导入后续模型。新增表和字段必须填写中文用途说明，并在变更业务含义时同步更新。

0025只修改注释，保留现有类型、默认值、可空性、精度、字符集、索引及约束，不提升最低兼容版本0024或code contract3。历史主题、旧免费数量等字段应按实际兼容用途理解，不能据注释恢复已停用入口。

## 执行与核验

1. 先在专用本地 `juya_verify` 验证新建库、已有数据升级、中断重试及锁超时；测试夹具不得连接真实业务库。
2. 核对实际目标库版本0024、56张表及390个字段（含Alembic版本表），保存一致性备份及原始结构。依次执行本地、远程测试、生产。
3. 远程使用已通过CI的管理API产物，沿用现有CLI独立 `migrate --environment test|production --project juya-admin-api --artifact <产物目录>`，不发布应用，不切换当前或回滚版本，不停止服务。
4. 迁移逐表执行注释差异，强制 `ALGORITHM=INPLACE, LOCK=NONE`，会话 `lock_wait_timeout=5` 并在结束时恢复原值。发生超时、不支持在线操作或清单不匹配时停止，不自动退回COPY或停机操作。
5. MySQL DDL可能部分成功；保留已完成说明，确认原因后重新升级至head。迁移跳过相同注释，不自动downgrade，不恢复整库覆盖线上新增业务数据。
6. 验收全部表和字段说明非空且与迁移清单一致、非注释结构不变、版本0025/contract3及服务健康。在线业务允许正常写入，不能要求迁移前后实时行数完全相同。

SQLite不支持持久化表/字段注释；本地SQLite仅更新Alembic版本，中文说明保存在模型中，不转换数据库或重建业务数据。MySQL数据库工具刷新结构后可在DDL、表信息及字段备注中查看说明。
