## 二 方案选择与现有差距

采用“明确类型及版本绑定，扩展现有业务链路”的方案。

| 方案 | 结果与代价 | 取舍 |
| --- | --- | --- |
| 由PDF推导分类，前端拆分已加载数据 | 无法满足管理员明确归属、先筛选后分页及发布隔离，历史已学也可能重现 | 排除 |
| 在现有稳定ID、草稿、发布及导入链路上增量扩展 | 需要一次扩展迁移和三仓联动，能保留成绩及素材并统一口径 | 推荐 |
| 为两类词汇建立独立内容与学习体系 | 需要复制发布、免费、成绩和收藏逻辑，增加跨系统一致性成本 | 排除 |

现有基础及需要改变的地方：

1. 小程序目前是“全部场景”和“含学习笔记”的包含关系；第二个列表请求 `scope=published&has_study_note=true`，会包括已学卡。本轮改成明确类型的两个互斥待学集合。
2. API已有稳定 `Card`、`CardDraft`、`CardVersion`，PDF又有独立 `CardStudyNoteVersion`。类型不能直接从PDF推算，也不能把类型塞进正文哈希后触发无关的排序和发音重建。
3. 场景来源匹配目前主要支持完整字面词且唯一位置；听读已经有部分词形和不规则表，但多处出现仍可能返回未匹配，比较级覆盖不完整，前端另有一份匹配规则。需要共用核心规则并减少前后端分歧。
4. 场景后台已有服务端页数和页码回退；听读已有服务端分页，返回结构尚无 `total_pages`。两页已有 Element Plus、免费模式和跨页稳定ID选择，可直接扩展。
5. 听读后台目前优先用 `draft_category_id` 筛选与展示。已有发布版的内容本轮必须按当前发布归属进入分类统计和列表，草稿归属单独标注。
6. 导入已有来源文件、目录、候选和判重信息；需要把重复原因和命中目标完整持久化展示，不能仅把重复数量变成一个临时弹窗。

## 三 业务规则和界面

### 雅思词汇双分类

- 首页入口仍叫“雅思词汇”，页面原“场景学习”及场景业务名称保留。分类为“图解词汇”和“精读词汇”，同一卡片只归一类，首次从首页进入默认图解。
- 图解词汇发布时不得有PDF；精读词汇发布时必须有已校验可用的PDF。PDF增删不自动改类型，类型与PDF冲突必须由管理员明确处理。
- 已登录集合：当前有效发布、未删除、当前类型、本人未完成；非免费未完成卡仍保留安全摘要，点击继续“暂未开放”。游客集合不按个人完成过滤，不显示虚构已学数字。
- 数量由服务端对完整匹配集合计数，再按现有 `is_free DESC, sort_order, id` 排序分页，不为分类另建排序或成绩。
- 完成成功并核实后才移出待学列表。提交超时或结果未知沿用原幂等操作重查，列表不提前减数或跳卡。分类变化、正文改版、PDF替换、取消收藏均不消除完成事实。
- “本类暂无词汇”由该类型有效发布数为0判断；“本类词汇已全部学完”要求本人已登录、该类型有效发布数大于0、本人待学数为0。仍有受限摘要或请求失败时不能显示全部学完。
- 全学完提供“查看学习记录”和“去另一类”。两个Tab始终可见；主动换Tab回顶部；详情、PDF、登录取消及登录成功返回恢复来源Tab、已读页和位置。登录成功只读刷新，不自动播放、打开PDF或提交完成。
- 视觉复用现有窗边绿植水彩、字体、场景卡片和状态组件；Tab采用自然文字宽度、32px间距、2px选中绿线、1px浅基线及至少44px点击高度。

### 后台类型及PDF

列表增加内容类型列和“全部类型／图解词汇／精读词汇”筛选；单篇新建、编辑及ZIP核对增加内容类型。未补类型或附件冲突可以保存待修正草稿，发布必须通过完整校验。

| 候选类型 | 候选有效PDF | 保存草稿 | 发布 |
| --- | --- | --- | --- |
| 未选择 | 任意 | 允许，显示待补类型 | 阻止 |
| 图解 | 无 | 允许 | 其他校验通过后允许 |
| 图解 | 有或待处理附件 | 允许，保留文件及冲突提示 | 阻止，明确改精读或移除 |
| 精读 | 有且校验通过 | 允许 | 其他校验通过后允许 |
| 精读 | 缺失、损坏、加密不可读或未完成处理 | 允许，保留旧有效附件及失败信息 | 阻止 |

所有发布入口，包括单篇、批量发布及异步任务，复用同一发布校验。预览指纹必须包含类型、PDF决策、有效附件及草稿版本；预览后改类型或PDF需重新核对。发布失败保留原发布类型、正文和附件，不能只切换其中一项。

### 导入核对

- 新场景DOCX模板增加“内容类型”，只接受两个中文值；听读模板不新增这两个类型或额外主题字段。旧包缺类型仍能解析为候选，在核对页补选。
- 文件内明确值优先。批量补选默认只填空值；明确覆盖已有值时，先显示稳定候选ID、原值、新值、数量和PDF冲突，确认后按候选版本应用。未知或多个类型值保留原文并逐项待核对。
- 导入候选移除仅影响候选，不删除已发布对象。重复项始终跳过，不参与类型批量覆盖、不提供重新勾选绕过判重。
- 沿用原保存和发布按钮；词形自动通过只减少来源核对，不替代图片、音频、释义、类型、PDF及听读归属的其他校验。

## 四 数据与发布设计

以下字段和新增文件名为拟定实现，现有路径按本次基线核对；最终契约在编码前导出评审。

### 明确类型的版本保存

建议沿用PDF独立版本模式，为类型增加一个小型不可变发布记录，避免为历史归类改写正文版本或重排场景。

| 数据位置 | 拟增内容 | 约束 |
| --- | --- | --- |
| `CardDraft` | 可空 `content_type` | 只接受 `illustrated`、`intensive`；空表示待补 |
| `ImportItem` | 可空 `content_type` 及来源信息 | 区分文件明确值、人工补选及覆盖；不是正式内容 |
| `CardContentTypeVersion` 新表 | card_id、递增版本、content_type、正文版本ID、PDF版本ID、管理员及时间 | 不可变，记录这次发布或历史确认所绑定的有效组合 |
| `Card` | 当前类型版本指针和可索引的 `published_content_type` 投影 | 两者与正文/PDF指针在同一事务切换，投影不能单独由页面写入 |
| `LearningQueue` | 可空 `content_type` 来源快照 | 仅待学来源使用，复习来源保持原语义 |
| 导入记录 | 重复原因、命中对象种类/ID、来源及标题快照 | 关联全批，目标不可用时仍能展示原始明细 |

发布读取同一草稿版本，锁定既有目录/对象，校验类型与有效附件，创建必要的正文、PDF及类型记录，最后一起切换当前指针。类型记录引用最终正文和PDF版本，用户查询不混读草稿。仅类型改变时不改稳定ID、正文哈希、既有学习排序或发音目标，不重新生成全文音频。

历史确认可在保持正文和PDF指针不变的情况下追加类型记录；不改写旧正文/PDF版本，不通过模拟正文重新发布来做归类。未来任一正文/PDF发布也必须校验并更新类型绑定，防止类型投影与当前版本失配。

数据库增加枚举值检查、外键、每卡类型版本唯一约束，以及按类型/发布状态查询所需索引。投影一致性由统一事务、迁移核验和完整性检查保证；不建立前端可独立更新的第二套分类事实。

### 历史核对及启用

1. 做扩展迁移，新增字段可空，不根据有无PDF自动回填正式分类。当前schema为0028，下一编号预计0029，实施时以实际迁移头为准。
2. 后台生成建议清单：仅检查当前有效发布PDF。有有效PDF建议精读，无有效PDF建议图解；异常引用、仅草稿有PDF、正文/PDF版本不一致单列。
3. 管理员明确选择并确认。确认快照包含稳定ID、当前正文/PDF版本、草稿版本和建议，提交时重验；并发变化返回待重新核对，逐项成功/失败可追溯，重复提交幂等。
4. 旧发布卡确认只更新当前发布的分类绑定；草稿尚未填类型时同步补入确认值，已有明确不同草稿值保留并标注待发布变更，不覆盖管理员编辑意图。
5. 启用前，在同一目录锁范围核验全部有效发布卡均有有效类型绑定和正确PDF组合，再开启分类就绪开关；发布入口同时受此规则约束，避免检查后又出现无类型发布卡。
6. 归类未完成时保留旧客户端可用的列表能力，新双分类入口暂不启用，并向新客户端返回未就绪状态；不能默默过滤未归类卡后宣称已启用。新功能启用后若发现绑定失配，报告配置异常并关闭双分类就绪能力，不以空列表代替故障。

本轮实现和演练在本地进行，自动化使用隔离的 `juya_verify`。保留所有稳定ID、完成档案、收藏、阅读位置、授权和打卡。后续上线时另行按获授权环境执行归类，不在本轮实际修改生产数据。

## 六 共用词汇来源匹配

### 服务端为最终判定

新增小型纯函数核心，由场景和听读适配各自正文结构与坐标，规则固定、可测试，不调用LLM推断词义或改写资料。覆盖完整词，常见复数、第三人称、过去式、分词、比较级及最高级和明确不规则变化；支持从原形到变形以及可可靠还原的反向匹配。

1. 保留原词条、词条ID和原释义，先验证现有来源是否仍与当前正文及该词的可靠词形对应。不能仅因坐标仍指向一段文字就保留错误关联。
2. 优先采用文件提供且与正文真实匹配的原句与位置；提供的明确原句和正文冲突时标该条待核对，不静默丢弃提示改绑其他句。
3. 没有原句时，完整词或可靠词形可定位即绑定。同词同义多处出现且无冲突时按正文顺序选首个有效位置，不能因多次出现增加人工确认。
4. 通过大小写、合理空白和排版标点的归一化建立到原文的索引映射；持久化原文实际词形、原句及精确范围，不能用归一化文本位置直接切原文。
5. 词形规则采用明确的常见规则及可审阅不规则表，不用任意去后缀或编辑距离。`art`不能命中`party`，`success`不等于`successful`，不能把近义词当词形。`better`等多候选或` saw `等可能产生不同来源解释的情况，依据资料原句消歧，仍不可靠则仅该条待核对。
6. 同拼写不同释义保持为独立词条，优先各自提供的来源；若不同义项竞争同一位置且无依据区分，才要求核对。保留既有合法重叠高亮，仅把互相矛盾的来源关联标成冲突。
7. 正文或词条修改后重跑，仍可靠自动通过；失效、无匹配、来源歧义、原句冲突、重叠冲突返回条目级原因及可读上下文，不阻断正常条目重新核对。

场景既有来源范围是每条对话内UTF-16偏移，听读是正文Unicode码点偏移，保持这两份契约，由适配层转换；必须用包含emoji、弯引号、换行及重复词的用例验证。来源的“资料词”和“正文实际词形”分别显示，不能拿原形音频代替正文变形，也不改变词数、正文音频、时间轴或当前查词开关。

### 前后端一致及导入身份

后台即时编辑使用同版本匹配规则提供预览，保存、导入和发布以服务端重跑结果为准；通过共享规则数据和同一组输入输出夹具约束两端。可靠结果显示“自动通过／无需手动确认”，不再以旧 `confirmed` 人工点击作为发布条件。现有明确的发音错误仍按原业务校验，不因来源通过而跳过。

匹配规则改变可能影响现有导入哈希。保留旧来源身份和历史摘要兼容比对，自动来源状态、算法版本及随机ID不能导致相同资料变成新内容；类型补选也不能成为用重复包修改既有卡分类的通道。实际英文、释义、素材等内容不同不能仅按标题判重，新增规范化算法以版本化方式兼容历史，不批量重算覆盖历史身份。

## 七 重复明细和批次恢复

重复计数旁提供“查看明细”，在当前导入流程内复用抽屉或弹窗，场景与听读统一列结构：源ZIP文件名、内部目录或DOCX名、中文/英文标题、重复原因、命中已有内容或保留的本批候选。

- 重复原因明确区分已有相同内容、同包重复、跨ZIP重复等实际判定结果；不是只有一个通用“重复”标签。
- 命中目标存储对象种类及稳定ID，避免把候选ID误当已入库文章ID跳转。目标后来删除、移除或不可访问时，原来源快照仍可读，查看入口禁用并显示真实状态。
- 全批次明细按服务端分页或受控滚动读取，不限定当前核对页或前三条；切页、返回和恢复持久批次后仍可查询。接口复用所属批次校验，不泄露其他管理员私有候选。
- 场景现有 `ImportItem`、`ImportIdentity` 和来源文件可扩展命中快照；听读现有 `duplicate_of` 补足目标种类及来源快照。只有现有记录无法稳定承载的信息才增加持久字段，不另建独立导入系统。
- 重复数与可查询明细使用同一事实集合，重试解析不能重复记数。重复、人工移除、不可读、处理失败分别统计；包数和卡片张数/文章篇数分开表达。
- 重复不新建、不覆盖、不进入本次可保存/发布集合，不删除源文件。后台重新勾选、批量补类型、恢复批次及保存重试均不能绕过此约束。

## 八 分类统计与手动跳页

### 四项统计

| 字段 | 计算口径 |
| --- | --- |
| 内容总数 | 当前分类所有未删除正式内容，含草稿、发布、下线，按稳定ID只计一次 |
| 已发布 | 当前有效发布且未删除，使用发布归属 |
| 已免费开放 | 上述已发布集合中当前 `is_free=true` 的数量 |
| 剩余可开启免费 | 已发布减已免费开放，不是名额或上限 |

统计只随分类变化，不随搜索、状态、页码或勾选缩小。比如总100、已发布80、免费30，剩余为50；草稿/下线保留免费标记也不计入已免费开放。列表的 `total` 则包含当前分类、搜索、状态和其他列表条件，是另一个口径。

两类后台请求均使用既有 `read_snapshot`，在同一 MySQL REPEATABLE READ 快照中读取列表总数、有效页、该分类统计及模块全部统计，并返回快照时间。用条件聚合计数，不联接多版本产生重复行，不下载全量资源到浏览器分页。

发布、下线、删除、已发布归属变化、单项或批量免费操作成功后，重读同一组合响应并使受影响分类及全部范围缓存失效。部分成功按真实任务结果刷新，不按所选数量前端加减。仅修改未发布草稿不能提前改变已有发布对象归属；从未发布草稿改变类型应刷新对应内容总数。

初次请求失败显示不可用和“统计加载失败，重试”；保留旧列表/统计时标明未刷新。组合响应未成功时不提交新页码或新统计，不能把异常写成0；真实0正常显示。若未来拆分请求，必须保持同一可核对快照，不仅各填一个当前时间。

### 跳页与选择

- 两页统一每页10条，保留上一页/下一页，增加“当前页／总页数”“前往［输入框］页”“跳转”。复用 `ElPagination`、`ElInput`、`ElButton` 和现有主题，不用组件库默认样式替代设计。
- 输入用文本模型保留原值，提交时去两端空白，以十进制整数字符规则校验，再验证安全整数及1至总页数范围；允许规范化前导零。空、0、负数、小数、字母、科学计数法、非安全整数和超范围原位提示，不发请求、不清输入或选择。
- 回车和按钮共用一次提交函数，输入和失焦不自动跳。当前页可直接返回；请求中防重。成功后才提交目标页并定位到表格顶部，保留搜索、分类、状态及排序。
- 免费模式上一页、下一页及手动跳页都保留稳定ID，已选总数、跨页数和返回页勾选准确；“选择本页”只操作该页。
- 普通发布/下线/删除仍只选本页，成功切页后才清空并提示。跳页失败保留旧数据、已提交页码、筛选及选择，可重试，不能先清选择后等接口。
- 改分类、搜索或状态回第1页；免费模式已有选择时先走原确认，取消恢复原控件、URL及勾选。请求代次与已提交查询快照分开，迟到响应不能覆盖新分类。
- 结果为空显示共0条及真实空态，跳页禁用，不显示第1／0页。删除或下线导致末页越界，使用服务端返回的最近有效页；编辑/预览返回恢复来源条件、有效页码及位置。

## 十二 风险和交付条件

最大的实施风险是历史归类、词形误配、发布/草稿口径及跳页失败时的状态丢失。分别用“人工确认后就绪”“服务端确定性规则及异常核对”“共用有效归属函数和同快照读取”“已提交状态与待请求状态分离”控制。

上线采用扩展迁移、先部署兼容API和后台、完成目标环境历史核对、再启用双分类及更新小程序的顺序。回退优先关闭新分类入口，保留新增类型和审计数据，不通过删除列或恢复旧库回滚；若旧代码曾修改正文/PDF，重新启用前必须重验绑定。本轮按用户新增授权在开发验收通过后执行测试环境部署，生产不操作。

方案评审重点为：明确类型采用独立发布记录；历史确认不改正文版本和排序；已发布对象的草稿改分类不提前影响统计；待学下一张锁定来源类型；词形可靠即通过但仍保留异常人工处理；所有统计和分页以服务端真实集合为准。授权与查词继续保持暂停。
