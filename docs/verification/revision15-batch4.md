# 修订15批4：公开分享摘要与展示副本

依据：已批准方案3.4、需求第34章、T179—T185，接口以 `docs/implementation/share-api-contract.md` 为准。仅本地开发与隔离合成数据验证；没有推送、部署或真实业务数据操作。

## 边界与实现

- 小程序API单独注册匿名摘要及图片GET／HEAD，后台不注册。专用DTO仅当前已发布双标题、稳定卡片／版本引用、两种图片地址及尺寸；不复用正文或个人资料DTO。
- 好友副本600×480，朋友圈600×600；真实静态PNG／JPEG／WebP解码，EXIF方向修正，全部像素等比contain留边，透明底合成浅色画布，JPEG去元数据。原始图片、数据库媒体记录及私有访问规则保持完整。
- 每次先检查当前发布与绑定版本，再限定读取源文件至预期size+1并核验长度及SHA256；缓存不能绕过源缺失／损坏、素材状态、下线／删除／换版。读取源后再查当前发布，避免读中发生停用仍返回旧图。
- 源字节限制取上传配置与20MiB的较小值；源像素最多20MP，编码副本最多1MiB。进程内编码LRU最多32项／8MiB，不在磁盘复制原图。
- 历史英文缺省、null、空串或纯空白统一返回空串，不伪造英文；非空正式标题保持原值。摘要只在两个实际副本准备成功后返回200。
- 明确404／410／409／422／503，坏PNG校验失败也为503；no-store与nosniff，HEAD复查与GET一致，不借Range或If-None-Match跳过校验。
- 不增加数据表、部署或服务；健康最低版本仍0015。公开读取不创建账号、学习开始／完成或Operation记录。
