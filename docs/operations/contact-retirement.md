# CHG-0039 历史联系方式退场

本工具交付数据库清理能力，**不代表本地业务库、远程数据库、缓存、日志或备份已经清理**。本轮自动化仅在临时 SQLite 直接构造历史记录验证；没有对应用真实库执行 `--apply`，没有访问远程服务或删除备份。用户选择先清空数据、暂留兼容空列，不在此次删除列或改写迁移历史。

## 精确清理范围

| 位置 | 行为 | 保留内容 |
| --- | --- | --- |
| `users` | 将 `phone_cipher`、`phone_digest`、`phone_source`、`wechat_cipher`、`wechat_digest`、`wechat_source`、`contact_updated_at` 置 `NULL` | 稳定用户 ID、用户编号、AppID/OpenID 摘要、昵称、头像、注册/登录时间、资料版本和时间、兼容 `contact_version` |
| `operations` 的 `action=contact.save` | 删除联系修改的整条幂等回执 | 其他操作及其键、指纹、受理时间 |
| `operations` 的 `action=profile.save` | 解密 `result`，剔除顶层 `phone`、`wechat_contact`、`phone_source`、`wechat_source`、`contact_version` 后重加密 | 其余结果字段及全部操作元数据 |
| `login_operations` 的非空 `result_cipher` | 不按过期时间过滤；解密后剔除 `user` 对象的同五个联系字段，再重加密 | `access_token`、有效期、其余顶层字段、其余 `user` 字段、幂等键、指纹及数据库过期时间 |
| `consents` 的 `purpose=contact.phone/contact.wechat` | 删除对应联系授权记录 | 协议/隐私及学习等其他授权记录 |

不触碰学习授权、收藏、完成事实、每日学习、打卡、听读进度、队列、内容、媒体和登录会话。无联系键的合法回执不重新加密，避免重试造成无意义变更。空登录回执跳过；无法解密、无效 JSON 或不符合对象结构的非空回执视为失败，不猜测、丢弃或冒称已清理。

## 副本盘点与待办

以下为代码和既有运维记录可确认的范围；远程实盘清单、数量和保留期限尚待维护窗口核对，不以源码检查代替远程验收。

| 副本/渠道 | 已知证据 | 执行前必须核对 |
| --- | --- | --- |
| 本机业务库和旧接续库 | `HANDOFF.md` 要求保留 Mac 原业务库，记录旧 schema 接续库/升级前备份；Windows 文档约定 `juya_local`，不能据此猜测本机实际库名 | 所有在用和停用数据库、旧工作树配置、旧预览库、转储及本机下载副本；逐项定环境与目标，防止遗漏 |
| 独立自动化库 | 仓库约定 MySQL `juya_verify`、临时 SQLite | 仅隔离测试夹具可清表；不得把真实业务库接入测试夹具 |
| 远程测试和生产库 | `HANDOFF.md` 保留双环境；[RDS 迁移记录](../verification/rds-production-migration-20261025.md)记录生产 RDS `juya_production` 及保留 ECS 同名源库 | 实际主机、端口、库名、复制实例/只读副本、旧源库、临时恢复库，分别确认是否包含联系数据；不能仅清理当前生产主库 |
| 登录与资料回执 | `models.py`、`content_models.py`、`auth.py`、`transactions.py` 记录加密幂等快照 | 同步清理本表清单，登录回执包含已过期记录；只清 `users` 仍可能从回执重放历史数据 |
| Redis | `worker.py` 中 Celery broker 只发送任务标识，业务载荷在数据库加密保存，无 Celery 结果后端；[本机分享文档](local-share.md)记录启用 Redis 持久化 | 远程实际 DB/命名空间、历史键、任务载荷、AOF/RDB、缓存代理/CDN 和浏览器/小程序存储均待实盘确认；当前源码未建立联系资料缓存，不能据此宣布历史缓存已清 |
| 应用/代理/运维日志 | `application.py` 对 API 响应设置 `Cache-Control: no-store`，请求异常只记角色、请求 ID、异常类型 | `no-store` 是响应缓存策略，不会删除历史缓存或日志。核对旧应用、反向代理、访问日志、慢 SQL、监控/APM、终端输出和运维回执是否记录过联系值及其保留周期 |
| 常规导出 | 当前 API 路由未见常规用户联系方式导出入口 | 人工 SQL 导出、临时脚本、客服/运营导出、下载副本需由持有人核对，不能推断不存在 |
| 备份 | [RDS 迁移记录](../verification/rds-production-migration-20261025.md)保留服务器/本机逻辑备份和原配置；`HANDOFF.md` 亦记录发布/迁移备份 | 核对 RDS 自动/日志备份、PITR、ECS/磁盘快照、人工转储和异地/本机下载副本的实际清单、访问权限与到期策略；记录中未独立核验过 RDS 自动备份策略 |

本脚本不支持 Redis `FLUSHDB/FLUSHALL`、按目录/通配符删除日志、备份或导出文件。远程缓存、日志、备份操作必须先形成包含实际对象、归属环境、保留/清理方式和责任人的清单，另行授权执行。

## 配置与运行

从工作区 `账号相关.txt` 只读取目标环境所需资料，放入已有私有环境配置；字段加密密钥必须与历史数据对应，不能重新生成。配置不入 Git，权限按现有运维规则限制（环境文件建议 `0600`，私密目录 `0700`）。不把连接 URL、密码、密钥或解密结果放到命令行、工单、日志或截图。

脚本通过 `Settings(_env_file=...)` 和 `make_database` 使用应用同样的连接方式，进程中的 `JUYA_*` 环境变量仍按 Settings 的既有优先级覆盖环境文件；执行前在私有终端核对环境。必须显式传入目标环境、数据库主机、端口和库名，与最终 Settings 不匹配会在建连前拒绝。分支名不决定数据库环境。命令行只传无凭据的目标标识，切勿将数据库 URL 当成主机/库名参数。

以下为模板，占位符需在目标维护窗口由执行人替换，不能原样执行；示例默认 **dry-run**：

```sh
.venv/bin/python scripts/cleanup-contact-data.py \
  --config /absolute/private/target.env \
  --environment test \
  --database-host EXPECTED_HOST \
  --database-port 3306 \
  --database-name EXPECTED_DATABASE \
  --batch-size 100
```

仅在当前任务已授权该目标的实际清理、完成清单和停写准备、复核 dry-run 后，以同一组参数追加 `--apply`。不要沿用历史部署/迁移授权。SQLite 只用于隔离验证，主机参数为 `local-file`，库名参数为实际文件路径；不在真实业务库上运行本文件测试。

维护窗口步骤：

1. 逐项核对实际目标、副本和历史数据加密配置；在私有清单记录主机/端口/库名与工具版本，避免在公开报告回显连接字符串。
2. 停止旧版本双 API、Worker、dispatcher 及其他写入者，阻断旧联系接口与旧回执重放；部署配套的联系方式退场版本后才能恢复流量，避免清理时又写回历史联系值。
3. 按现有流程制作可恢复的一致性备份、核验恢复能力并限制访问。该备份仍含待清理历史联系数据，要登记其实际生命周期。
4. 使用同一私有配置和显式目标执行 dry-run，保存仅含计数/状态的报告。`incomplete` 需要先解决密钥/数据结构/数据库异常，不视为可完成的预检。
5. 获得本次目标的实际清理授权后执行 `--apply`，保存无密报告，状态须为 `complete`。再次 dry-run，五类变更计数均为 `0`，同时只读核对稳定账号、学习授权和学习事实保持。
6. 依清单分别处理其他数据库副本和外部渠道，逐项登记证据；直到全部确认前，不把整项历史数据清理标记为完成。

## 事务、重试与报告

按主键游标分页，每批独立事务，不使用删除后会跳行的 OFFSET。默认每批 100 行，可用 `--batch-size` 调整正整数。dry-run 不发出业务 DML，读事务回滚；实际执行按批提交。每批处理失败（包括回执解密失败和写入/提交失败）时回滚该批，立即停止后续批次，返回 `incomplete` 和非零退出码。此前已提交批次保留，可在原因修复后用相同参数幂等重试；无需手工回滚成功批次。数据库断连时不能仅凭客户端错误推断服务端提交状态，仍应通过幂等重试和最终零候选复核确认。

报告只含状态和计数，不含用户 ID、联系方式、密文、令牌、指纹、SQL、URL、配置或异常字符串。`users_cleared`、`contact_operations_deleted`、`contact_consents_deleted`、`profile_receipts_cleaned`、`login_receipts_cleaned` 为已提交变更数（dry-run 为拟变更数）；失败批次不计入变更数。另含扫描行数、成功/失败批次数、回执失败数。回执失败数表示触发失败的批次中已发现的异常，**不是全库异常总数**，因为工具立即停止。状态 `configuration_error` 返回 2；`failed`/`incomplete` 返回 1；成功 dry-run/执行返回 0。

## 备份与恢复约束

不为此次任务猜测或修改备份周期。由运维在清单中登记每类备份实际保留周期、最早/最晚到期时间、PITR覆盖区间、存储位置类别和访问责任人；按已批准的实际周期到期清理，未到期且必须保留的含历史数据备份维持严格访问限制，不供业务查询或常规导出。现有文档里的备份建议不等于实际生效策略。

任何含旧联系数据的备份恢复，都必须先进入**隔离且不对外服务的环境**，使用匹配密钥离线运行此清理工具，并核对回执、其他副本和变更计数归零，再接入已退场版本并恢复上线。不得将旧备份直接覆盖已清理在线库，亦不得通过回滚旧应用重新开放联系方式写入。
