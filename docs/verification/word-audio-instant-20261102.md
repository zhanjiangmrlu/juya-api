# 正文单词发音预生成与预加载（2026-11-02）

## 本轮实现

针对录屏中场景正文查词弹窗 `car`、`police` 点读等待，采用用户确认的发布后预生成、进入场景预下载、跨弹窗复用方案。基线先快进本地已有 `origin/test` 快照：API `dcfff30`、Mini `33078e4`，保留整合06既有修复、私有配置和数据。

- 发布在原事务中接受绑定 card/version/语音配置的幂等预热任务，worker 每批32个精确正文引用；重复读音复用全局缓存，同形异音保持隔离
- 普通任务先派发，每角色全局只接纳一个未完成预热子任务；使用现有表保存闸门和派发状态，不新增迁移
- 主动点词可将尚未运行的预热提升为普通任务，运行中共享；发布/下线与预热完成按 actor→catalog→job→cache 串行重核，失效任务跳过
- 保留预算、冷却、重试和短期票据；服务未配置不扣云调用预算，失败及跳过任务允许明确重试/重新发布后恢复
- 小程序按精确引用预取全部正文，可见内容优先，后台两个 GET 通道；processing 延后重排，不自动合成或播放
- 弹窗打开时与释义并行准备，关闭只取消选择，文件属于页面；四分钟窗口从取址开始计算，隐藏/离页/会话/版本/权限变化清理
- 缓存正文分词并按120ms合并视口测量；测量在途只保留最新请求，避免滚动重复处理全文

HTTP契约及schema不变，仍逐次联网验权；重点词汇和完整音频播放沿用原实现。本轮未改主题听读的发音流程。

## 已有场景补热

API配置由私有环境提供。默认仅预览当前发布卡片及按实际读音缓存去重的 ready、processing、待生成和无效词数，不写任务：

```sh
uv run python scripts/prewarm-pronunciation.py --card-id <场景ID>
```

只有显式 `--execute` 且配置为本地环境和本地数据库，才接受指定已发布场景的持久任务；仍由既有worker执行、遵守预算和冷却：

```sh
uv run python scripts/prewarm-pronunciation.py --card-id <场景ID> --execute
```

本轮未对业务场景执行补热、未提交/推送、未部署、未上传体验版。代码构建通过不表示手机体验包已更新。
